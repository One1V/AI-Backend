## **Question:**

### **Why do backend developers learn Linux deployment instead of relying only on Vercel or Render?**

### **Answer:**

When we use platforms like **Vercel** or **Render**, they automatically perform all the deployment steps for us. We simply connect our GitHub repository and click **Deploy**.

Behind the scenes, they:

* Create a Linux server
* Install Node.js
* Clone the GitHub repository
* Install dependencies (`npm install`)
* Set environment variables
* Start the application
* Keep it running
* Configure HTTPS
* Handle restarts if the application crashes

As backend developers, we learn Linux deployment because we should understand **how these steps happen internally**, not just how to click a Deploy button.

This knowledge helps us:

* Deploy applications on our own Linux server (AWS EC2, Azure VM, DigitalOcean, etc.).
* Debug production issues when an application goes down.
* Configure Nginx, PM2, or `systemd`.
* Manage logs, permissions, networking, and services.
* Work in companies that use self-managed servers instead of managed platforms.

### **Simple Interview Answer (30 seconds)**

> We learn Linux deployment to understand what happens behind the scenes when an application is deployed. Platforms like Vercel and Render automate deployment, but companies often use their own Linux servers. Knowing Linux allows us to deploy applications manually, configure servers, debug production issues, and manage backend services without depending on a managed platform.
