# **Question 2. What is the Linux Kernel?**

# First, what does "kernel" mean?

The **kernel** is the **core part of an operating system**.

It is the first major software loaded after the computer boots, and it stays running until the computer shuts down.

Think of it as the **manager between applications and hardware**.

---

# Why do we need a kernel?

Imagine there were no kernel.

Suppose your Express application wanted to:

* read a file
* use RAM
* send data over the Internet

It would need to know:

* how SSDs work
* how RAM is allocated
* how CPUs schedule tasks
* how Ethernet/Wi-Fi works
* how USB devices communicate

Every application would need to implement all of this.

That would be incredibly difficult and unsafe.

Instead, the kernel provides a common interface.

---

# Real backend example

Suppose your Express server has:

```javascript
const fs = require("fs");

fs.readFile("users.json", (err, data) => {
    console.log(data.toString());
});
```

But what actually happens?

```text
Express
      ↓
Node.js fs module
      ↓
Linux Kernel
      ↓
SSD
      ↓
Kernel reads file
      ↓
Node.js
      ↓
Your callback runs
```

Your code never talks directly to the SSD.

The kernel does.

---

# Another example

You write:

```javascript
app.listen(5000);
```

Looks simple.

Internally:

```text
Express
      ↓
Node.js
      ↓
Kernel
      ↓
Network Stack
      ↓
Port 5000 reserved
```

The kernel:

* checks whether port 5000 is already in use,
* reserves it if available,
* starts listening for incoming connections.

If another application already uses that port, the kernel refuses the request, and Node.js reports an error such as:

```text
EADDRINUSE
```

The kernel is enforcing the rule that only one process can bind to a given IP/port combination.

---

# Main responsibilities of the kernel

## 1. Process Management

The kernel creates, schedules, and stops processes.

Example:

```text
Chrome
VS Code
Node.js
MongoDB
Spotify
```

The CPU can execute only a limited number of instructions at a time.

The kernel rapidly switches between processes so they all appear to run simultaneously.

---

## 2. Memory Management

Suppose:

```text
Node.js
needs 300 MB

Chrome
needs 2 GB

MongoDB
needs 800 MB
```

The kernel decides:

* how much memory each process gets,
* where it is stored,
* and prevents one process from reading another process's memory.

Without this protection, one buggy application could corrupt another.

---

## 3. File Management

When you run:

```bash
cat users.txt
```

The kernel:

* locates the file,
* checks permissions,
* reads it from disk,
* returns the data.

If you don't have permission, the kernel blocks the operation.

---

## 4. Device Management

Every hardware device communicates through the kernel.

Examples:

* SSD
* keyboard
* mouse
* webcam
* Wi-Fi adapter
* Ethernet
* GPU

Applications use standard interfaces; the kernel handles the hardware-specific details.

---

## 5. Networking

When someone visits:

```text
https://yourdomain.com/api/users
```

The kernel:

* receives network packets,
* passes them to Nginx,
* lets Nginx forward them to Express,
* sends the response back.

The kernel is the foundation of Linux networking.

---

# What is a system call?

Applications **cannot directly access hardware**.

Instead, they ask the kernel using **system calls**.

Think of a system call as an official request to the kernel.

Examples:

```text
Application
      ↓
System Call
      ↓
Kernel
      ↓
Hardware
```

Common requests include:

* open a file,
* read data,
* write data,
* allocate memory,
* create a process,
* open a network socket.

You won't usually write system calls directly in backend development, but many Node.js APIs eventually use them.

---

# Backend engineer's perspective

Whenever your application:

* reads a file,
* writes logs,
* opens a port,
* accepts HTTP requests,
* connects to MongoDB,
* allocates memory,

the kernel is working behind the scenes.

---

# Interview questions

### Q1. What is the Linux kernel?

A good answer:

> The Linux kernel is the core component of the operating system. It manages hardware resources and provides services such as process management, memory management, file systems, device management, and networking for applications.

---

### Q2. Does Node.js talk directly to hardware?

No.

```text
Node.js
      ↓
Linux Kernel
      ↓
Hardware
```

---

### Q3. Is Linux the same as the kernel?

Not exactly.

* **Linux kernel** = the core software.
* **Linux distribution** (such as Ubuntu) = the kernel plus utilities, package manager, shell, libraries, and applications.

We'll cover distributions in the next lesson.

# Key takeaways

* The **kernel** is the core of the operating system.
* Applications don't access hardware directly—they go through the kernel.
* The kernel manages:

  * Processes
  * Memory
  * Files
  * Devices
  * Networking
* Almost every backend operation (`fs.readFile`, `app.listen`, database connections, HTTP requests) ultimately relies on the kernel.
