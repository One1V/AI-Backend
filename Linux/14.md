# Module 2 – Navigation & Files

# **Question 14. How do `ls`, `-l`, `-a`, and `-h` work?**

The `ls` command means:

> **List** files and directories.

Think of it as asking Linux:

> **"What is inside this folder?"**

---

# 1. `ls`

Suppose your current directory is:

```text
/home/ayush/backend
```

Inside it:

```text
backend/
│
├── server.js
├── package.json
├── routes/
├── controllers/
└── node_modules/
```

Run:

```bash
ls
```

Output:

```text
controllers
node_modules
package.json
routes
server.js
```

`ls` simply lists the contents.

---

# Why do backend developers use `ls`?

Imagine you cloned a project.

```bash
git clone <repo>
cd backend
```

Now you want to check whether the files exist.

```bash
ls
```

You immediately see:

```text
package.json
server.js
README.md
```

---

# 2. `ls -l`

The `-l` means:

> **Long Listing Format**

Instead of only names, Linux shows extra information.

Example:

```bash
ls -l
```

Output:

```text
-rw-r--r-- 1 ayush ayush   520 Aug 5 10:30 package.json
-rw-r--r-- 1 ayush ayush  2048 Aug 5 10:35 server.js
drwxr-xr-x 2 ayush ayush  4096 Aug 5 10:40 routes
```

Let's understand one line:

```text
-rw-r--r-- 1 ayush ayush 520 Aug 5 10:30 package.json
```

It contains:

```text
Permissions
↓

-rw-r--r--

Owner
↓

ayush

Group
↓

ayush

Size
↓

520 bytes

Modified Date
↓

Aug 5 10:30

Filename
↓

package.json
```

Don't worry about permissions yet—we'll study them in Module 4.

---

# 3. `ls -a`

Normally, Linux hides files whose names start with a dot (`.`).

Example:

```text
.env
.git
.gitignore
```

If you run:

```bash
ls
```

Output:

```text
package.json
server.js
routes
```

You **won't** see `.env`.

Now run:

```bash
ls -a
```

Output:

```text
.
..
.env
.git
.gitignore
package.json
routes
server.js
```

Now the hidden files are visible.

---

## Why is this important?

Backend projects often contain:

```text
.env
```

If you can't find it, don't panic.

Run:

```bash
ls -a
```

You'll see it.

---

# What are `.` and `..`?

Notice:

```text
.
..
```

These are special directories.

* `.` = Current directory
* `..` = Parent directory

You'll use them frequently.

---

# 4. `ls -h`

The `-h` means:

> **Human Readable**

It is usually combined with `-l`.

Example:

```bash
ls -lh
```

Instead of:

```text
1048576
```

you'll see:

```text
1.0M
```

Instead of:

```text
2048
```

you'll see:

```text
2.0K
```

This makes file sizes much easier to understand.

---

# 5. Combine Options

Linux allows combining options.

Example:

```bash
ls -lah
```

This means:

* `-l` → Long format
* `-a` → Show hidden files
* `-h` → Human-readable sizes

Example output:

```text
drwxr-xr-x  5 ayush ayush 4.0K Aug 5 11:20 .
drwxr-xr-x 10 ayush ayush 4.0K Aug 5 11:00 ..
-rw-r--r--  1 ayush ayush  250 Aug 5 11:15 .env
-rw-r--r--  1 ayush ayush 1.2K Aug 5 11:10 package.json
-rw-r--r--  1 ayush ayush 3.5K Aug 5 11:12 server.js
```

This is a command you'll use constantly.

# Real Backend Example

Suppose someone says:

> "Your `.env` file is missing."

You check:

```bash
ls
```

Output:

```text
package.json
server.js
```

You think:

> "Where is `.env`?"

Then you remember:

```bash
ls -a
```

Output:

```text
.env
.git
package.json
server.js
```

Problem solved.

---

# Another Example

You want to know the size of uploaded files.

Run:

```bash
ls -lh uploads
```

Example:

```text
5.2M image.png
320K report.pdf
```

Much easier than reading raw byte counts.

# Interview Questions

### Q1. What does `ls` do?

**Answer:**

> It lists the files and directories in the current directory.

---

### Q2. What does `ls -l` do?

**Answer:**

> It displays files in a detailed format, including permissions, owner, size, modification date, and filename.

---

### Q3. Why use `ls -a`?

**Answer:**

> To display hidden files and directories, such as `.env` and `.git`.

---

### Q4. What does `ls -lh` do?

**Answer:**

> It displays file information in long format with human-readable file sizes.
