## **Question 15. How do `mkdir`, `rmdir`, and `touch` work?**

These commands are used to **create and remove** directories and files.

---

# 1. `mkdir` — Make Directory

`mkdir` stands for:

> **Make Directory**

# Create Multiple Directories

Instead of:

```bash
mkdir routes
mkdir controllers
mkdir models
```

You can write:

```bash
mkdir routes controllers models
```

Output:

```text
backend/
│
├── routes
├── controllers
└── models
```

---

# 2. `mkdir -p`

Suppose you want to create:

```text
backend/src/controllers
```

But neither `backend` nor `src` exists.

This fails:

```bash
mkdir backend/src/controllers
```

Because the parent directories don't exist.

Instead use:

```bash
mkdir -p backend/src/controllers
```

Linux creates everything automatically:

```text
backend/
└── src/
     └── controllers/
```

The `-p` option means:

> **Create parent directories if they don't exist.**

---

# 3. `touch`

`touch` creates a new **empty file**.

### Example

```bash
touch server.js
```

# Create Multiple Files

```bash
touch server.js app.js .env README.md
```

# What if the File Already Exists?

Suppose:

```bash
touch server.js
```

and `server.js` already exists.

It **doesn't delete or overwrite** the file.

It simply updates the file's **last modified timestamp**.

---

# 4. `rmdir`

`rmdir` removes an **empty directory**.

Example:

```bash
mkdir temp
```

Now remove it:

```bash
rmdir temp
```

Done.

---

# Important Limitation

Suppose:

```text
backend/
└── routes/
```

Run:

```bash
rmdir backend
```

Linux says:

```text
Directory not empty
```

Because `backend` contains `routes`.

`rmdir` only works on **empty** directories.

---

# 🧠 Memory Trick

Remember:

```text
mkdir  → Make Folder

mkdir -p → Make Folder + Parent Folders

touch → Create File

rmdir → Remove Empty Folder
```
