## **Question 16. How do `cp`, `mv`, and `rm` work?**

These commands are used to:

* Copy files
* Move files
* Rename files
* Delete files

---

# 1. `cp` — Copy

---

## Example 1 — Copy a File

Suppose:

```text
backend/
│
└── .env
```

Run:

```bash
cp .env .env.backup
```

Now:

```bash
ls -a
```

Output:

```text
.env
.env.backup
```

The original file is still there.

---

## Why is this useful?

Before changing your `.env`, make a backup.

```bash
cp .env .env.backup
```

If you make a mistake, you still have the original.

---

## Example 2 — Copy a Directory

Suppose:

```text
backend/
└── uploads/
```

If you run:

```bash
cp uploads backup
```

Linux says:

```text
cp: -r not specified
```

Because `uploads` is a directory.

Use:

```bash
cp -r uploads backup
```

`-r` means:

> **Recursive** (copy everything inside the directory).

---

# 2. `mv` — Move

It moves a file or folder to another location.

---

## Example

```bash
mv server.js src/
```

Before:

```text
backend/
│
├── server.js
└── src/
```

After:

```text
backend/
└── src/
     └── server.js
```

The file is **moved**, not copied.

---

# `mv` is also used to Rename

Suppose:

```text
app.js
```

Rename it:

```bash
mv app.js server.js
```

Now:

```text
server.js
```

No new file is created.

The old name is simply changed.

---

### 3. `rm` — Remove

It deletes files.

---

## Example

```bash
rm hello.txt
```

---

# Delete Multiple Files

```bash
rm file1.txt file2.txt file3.txt
```

All are deleted.

---

# Delete a Directory

Suppose:

```text
uploads/
│
├── img1.png
└── img2.png
```

`rmdir` won't work because the directory isn't empty.

Instead:

```bash
rm -r uploads
```

`-r` means:

> Delete recursively.

Linux deletes:

* Directory
* Files
* Subdirectories

Everything.

---

# Be Careful with `rm`

Unlike Windows:

```text
Delete

↓

Recycle Bin
```

Linux:

```text
rm file.txt

↓

Gone immediately ❌
```

There's usually **no recycle bin** when using `rm` in the terminal.

---

# The Dangerous Command

You've probably seen this:

```bash
rm -rf /
```

Let's break it down:

* `-r` → Recursive
* `-f` → Force (don't ask for confirmation)

Historically, on systems that allowed it, this could attempt to remove everything starting from the root directory (`/`).

**Modern Linux distributions include strong protections against this exact command**, and it is blocked by default in common implementations like GNU `rm`. Still, **never run destructive `rm` commands unless you fully understand what they will delete.**

---

# Interview Questions

### Q1. What does `cp` do?

**Answer:**

> It copies files or directories to another location. Use `-r` when copying directories.

---

### Q2. What does `mv` do?

**Answer:**

> It moves files or directories. It is also used to rename them.

---

### Q3. What does `rm` do?

**Answer:**

> It deletes files. Use `rm -r` to delete directories and their contents.

---

### Q4. Why should you be careful with `rm`?

**Answer:**

> Because it permanently deletes files from the terminal in most environments, and recovery is not guaranteed.

# Backend Engineer's Perspective

These commands are used constantly:

```bash
cp .env.example .env
```

Create your project's environment file.

```bash
mv app.js server.js
```

Rename your main file.

```bash
rm -r dist
```

Delete an old build before creating a new one.

```bash
cp -r uploads backup
```

Back up uploaded files.

# 🧠 Memory Trick

```text
cp → Copy

mv → Move / Rename

rm → Remove

rm -r → Remove Folder

cp -r → Copy Folder
```

## 🔥 Placement Tip

A common interview question is:

> **"How do you rename a file in Linux?"git add .**

Many beginners answer:

> "There is a `rename` command."

While Linux does have utilities named `rename` on many systems, the **standard and most commonly expected answer** is:

```bash
mv oldname.txt newname.txt
```

Using `mv` to rename files is what you'll see in everyday backend development and deployment.
