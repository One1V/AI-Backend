# **Question 19. What are Symbolic Links and Hard Links?**

---

## First, what is a Link?

A **link** is like a **shortcut** to a file.

Real-life example:

Imagine your favorite movie is stored in:

```text
D:\Movies\Avengers.mp4
```

Instead of copying the 5 GB movie to your Desktop, you create a **shortcut**.

Now:

```text
Desktop
│
└── Avengers Shortcut
```

When you double-click the shortcut, Windows opens the original movie.

Linux has a similar concept called **links**.

There are two types:

1. Symbolic Link (Soft Link)
2. Hard Link

---

# 1. Symbolic Link (Soft Link)

A symbolic link is **like the shortcut you see in Windows**.

It doesn't store the actual file.

It stores **the path to the file**.

---

### Example

Original file:

```text
/home/ayush/project/server.js
```

Create a symbolic link:

```bash
ln -s /home/ayush/project/server.js shortcut.js
```

Now:

```text
shortcut.js
      │
      ▼
/home/ayush/project/server.js
```

When you open `shortcut.js`, Linux automatically opens `server.js`.

# 2. Hard Link

A hard link is **not a shortcut**.

Think of it as **another name for the same file**.

Example:

Original:

```text
report.txt
```

Create hard link:

```bash
ln report.txt report-copy.txt
```

Now:

```text
report.txt
report-copy.txt
```

Both refer to the **same underlying file**.

---

## What happens if the original is deleted?

Delete:

```bash
rm report.txt
```

Result:

```text
report-copy.txt
```

still works perfectly.

Because both names point to the same file data.

---

# Visual Difference

## Symbolic Link

```text
shortcut
     │
     ▼
original file
```

Delete original:

```text
shortcut
     │
     ▼
Nothing ❌
```

Broken.

---

## Hard Link

```text
report.txt
       │
       ▼
   Actual Data
       ▲
       │
report-copy.txt
```

Delete one name:

```text
report-copy.txt
       │
       ▼
   Actual Data ✅
```

The data remains because another hard link still points to it.

---

# Commands

### Create Symbolic Link

```bash
ln -s original.txt shortcut.txt
```

---

### Create Hard Link

```bash
ln original.txt hardlink.txt
```

Notice:

No `-s`.

---

# Interview Questions

### Q1. What is a symbolic link?

**Answer:**

> A symbolic link is a special file that stores the path to another file or directory. If the original is deleted, the symbolic link becomes broken.

---

### Q2. What is a hard link?

**Answer:**

> A hard link is another directory entry that points to the same underlying file data. Deleting one name does not remove the data as long as another hard link still exists.

---

### Q3. Which one behaves like a Windows shortcut?

**Answer:**

> Symbolic link.

---

### Q4. Which one survives deletion of the original filename?

**Answer:**

> Hard link.

---

# Do you need to remember all the technical details?

For **backend internships**, you mainly need to remember:

| Symbolic Link                               | Hard Link                                                  |
| ------------------------------------------- | ---------------------------------------------------------- |
| Like a shortcut                             | Another name for the same file                             |
| Can point to files**and directories** | Typically used with files (not directories in normal use)  |
| Breaks if the original target is removed    | Continues working as long as at least one hard link exists |

You don't need to dive into filesystem internals (like inode numbers) right now.

# 🧠 Memory Trick

Think of it this way:

**Symbolic Link**

> 📍 "Go to this address."

If the house is demolished, the address leads nowhere.

**Hard Link**

> 🏷️ "This house has two names."

Remove one nameplate, and the house is still there.
