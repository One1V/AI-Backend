
## **How does `grep` work?**

⭐ **Importance:** **10/10**

`grep` lets you **search for text inside files**.

Think of it as **Ctrl + F for the Linux terminal**.

---

# Why do we need `grep`?

Suppose your log file has **50,000 lines**.

You only want to find lines containing the word:

```text
ERROR
```

Reading the entire file is impossible.

Instead:

```bash
grep "ERROR" server.log
```

Linux shows **only the matching lines**.

---

# Example

Suppose `server.log` contains:

```text
Server Started
MongoDB Connected
GET /users
ERROR Database Connection Failed
POST /login
ERROR Invalid Token
Server Closed
```

Run:

```bash
grep "ERROR" server.log
```

Output:

```text
ERROR Database Connection Failed
ERROR Invalid Token
```

Only the lines containing `ERROR` are displayed.

---

# Backend Example 1

Find all login requests:

```bash
grep "login" server.log
```

Output:

```text
POST /login
User login successful
```

---

# Backend Example 2

Find MongoDB logs:

```bash
grep "MongoDB" server.log
```

Output:

```text
MongoDB Connected
```

---

# Case Sensitivity

By default, `grep` is **case-sensitive**.

Suppose:

```text
Error
ERROR
error
```

Run:

```bash
grep "ERROR" server.log
```

Output:

```text
ERROR
```

It does **not** match `Error` or `error`.

---

# Ignore Case (`-i`)

```bash
grep -i "error" server.log
```

Output:

```text
Error
ERROR
error
```

This is very common.

---

# Show Line Numbers (`-n`)

```bash
grep -n "ERROR" server.log
```

Output:

```text
4: ERROR Database Connection Failed
6: ERROR Invalid Token
```

Now you know **where** the match occurred.

---

# Count Matches (`-c`)

Instead of showing the lines:

```bash
grep -c "ERROR" server.log
```

Output:

```text
2
```

Useful for quickly checking how many errors occurred.

---

# Search Multiple Files

Suppose:

```text
logs/
├── app.log
├── auth.log
└── nginx.log
```

Search all log files:

```bash
grep "ERROR" *.log
```

Output:

```text
app.log: ERROR Database Failed
auth.log: ERROR Invalid Password
```

Notice how globbing (`*.log`) and `grep` work together.

---

# Combine with `tail`

This is common in production:

```bash
tail server.log | grep "ERROR"
```

Meaning:

1. Read the latest log entries.
2. Show only the ones containing `"ERROR"`.
