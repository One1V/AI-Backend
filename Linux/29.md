## **How do Pipes (`|`) work?**

⭐ **Importance:** **10/10 (Must Know)**

# What is a Pipe?

A **pipe (`|`)** takes the **output of one command** and sends it as the **input to another command**.

Think of it like a water pipe.

```text
Command 1
     │
(Output)
     │
     ▼
    Pipe (|)
     │
(Input)
     ▼
Command 2
```

Instead of saving output to a file, Linux directly passes it to the next command.

---

# Example 1

```bash
cat server.log | grep "ERROR"
```

Output:

```text
ERROR
ERROR
```

### What happened?

1. `cat server.log` → Reads the file.
2. `|` → Sends the output to the next command.
3. `grep "ERROR"` → Keeps only the matching lines.

---

# Real Backend Example

Suppose your access log is:

```text
GET /users
POST /login
GET /products
POST /login
```

Find only login requests:

```bash
cat access.log | grep "login"
```

Output:

```text
POST /login
POST /login
```

---

Now count them:

```bash
cat access.log | grep "login" | wc -l
```

Output:

```text
2
```

---

# Why are Pipes Powerful?

Without pipes, you might:

1. Run one command.
2. Copy its output.
3. Save it somewhere.
4. Run another command.

With pipes:

Everything happens automatically.

# Interview Questions

### Q1. What is a pipe?

**Answer:**

> A pipe (`|`) passes the output of one command as the input to another command.

---

### Q2. What does this command do?

```bash
grep "ERROR" server.log | wc -l
```

**Answer:**

It counts how many lines in `server.log` contain `"ERROR"`.

---

### Q3. Why are pipes useful?

**Answer:**

They let you combine multiple commands without creating intermediate files, making command-line workflows faster and more efficient.
