# **Mini Project: Analyze an Express Server Log Using Linux Commands**

⭐ **Importance:** **10/10**

This is exactly the kind of task you'll perform when debugging a backend application.

---

# Scenario

Your Express app generated this log file:

```text
server.log
```

Contents:

```text
INFO Server Started
INFO MongoDB Connected
GET /users 200
POST /login 200
ERROR Invalid Token
GET /products 200
ERROR Database Connection Failed
POST /signup 201
```

Your job is to analyze it using Linux commands.

---

# Task 1: View the Entire Log

```bash
cat server.log
```

---

# Task 2: View Only the Last Few Lines

```bash
tail server.log
```

Useful when the log file is very large.

---

# Task 3: Monitor New Logs Live

```bash
tail -f server.log
```

As new requests arrive, they appear automatically.

Press **Ctrl + C** to stop.

---

# Task 4: Find All Errors

```bash
grep "ERROR" server.log
```

Output:

```text
ERROR Invalid Token
ERROR Database Connection Failed
```

---

# Task 5: Count the Errors

```bash
grep "ERROR" server.log | wc -l
```

Output:

```text
2
```

---

# Task 6: Find Only Login Requests

```bash
grep "/login" server.log
```

Output:

```text
POST /login 200
```

---

# Task 7: Count Total Log Entries

```bash
wc -l server.log
```

Output:

```text
8
```

---

# Task 8: Find the Log File

If you don't remember where it is:

```bash
find . -name "server.log"
```

---

# What Did You Use?

| Command     | Purpose      |                  |
| ----------- | ------------ | ---------------- |
| `cat`     | View file    |                  |
| `tail`    | Last lines   |                  |
| `tail -f` | Monitor live |                  |
| `grep`    | Search text  |                  |
| `wc -l`   | Count lines  |                  |
| `find`    | Locate file  |                  |
| `           | `            | Combine commands |

These are the commands you'll use repeatedly in real backend work.

---

# Real Production Example

Imagine a user reports:

> **"Login is not working."**

A backend developer might SSH into the server and run:

```bash
tail -f server.log
```

Then ask the user to try logging in again.

If an error appears, they can filter it:

```bash
grep "ERROR" server.log
```

or count how often it has occurred:

```bash
grep "ERROR" server.log | wc -l
```

This is a typical production debugging workflow.
