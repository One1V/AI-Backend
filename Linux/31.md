# **Why does Linux have permissions?**

⭐ **Importance:** **10/10 (Must Know)**

Every backend developer who deploys applications on Linux should understand this.

---

# Imagine There Were No Permissions...

Suppose a server has three users:

* Ayush (Backend Developer)
* Rahul (Frontend Developer)
* Admin

Without permissions:

* Rahul could delete your backend code.
* Anyone could read your `.env` file (database password, JWT secret).
* Someone could modify Nginx configuration.
* Anyone could stop your Node.js server.

That would be a huge security risk.

Linux solves this with **permissions**.

---

# What are Linux Permissions?

Permissions decide:

* **Who can read a file?**
* **Who can modify a file?**
* **Who can execute (run) a file?**

Think of permissions as a lock on every file and folder.

---

# Real Backend Example

Suppose your project contains:

```text
backend/
│
├── server.js
├── package.json
├── .env
└── uploads/
```

Your `.env` contains:

```text
MONGO_URI=...
JWT_SECRET=...
```

If everyone on the server could read `.env`, they would know:

* Database password
* JWT secret
* API keys

That's why permissions are important.

---

# Another Example

Suppose `server.js` has:

```javascript
app.listen(5000);
```

If another user changes it to:

```javascript
app.listen(8000);
```

Your application may stop working.

Permissions prevent unauthorized changes.

---

# File vs Folder Permissions

### File

Permissions control:

* Read the file
* Edit the file
* Execute the file (if it's a script or executable)

Example:

```text
server.js
```

---

### Folder

Permissions control:

* Enter the folder
* List its contents
* Create or delete files inside it (depending on permissions)

Example:

```text
backend/
```

---

# Real Production Example

Imagine a Linux server running:

* Nginx
* Express
* MongoDB

The Node.js process needs permission to:

* Read `.env`
* Read project files
* Write log files
* Save uploaded images

But it **should not** be able to modify important system files like:

```text
/etc/passwd
```

Linux permissions enforce these boundaries.

---

# Why Backend Developers Care

Many deployment problems happen because of incorrect permissions.

Examples:

* ❌ `Permission denied`
* ❌ Cannot read `.env`
* ❌ Cannot write uploaded files
* ❌ Nginx cannot access static files

Knowing permissions helps you debug these issues quickly.

---

# Minimum Required

Understand that Linux permissions exist to:

* Protect files.
* Control who can read, write, and execute them.
* Keep systems secure, especially on shared servers.

You don't need to memorize permission syntax yet—we'll learn that in the next few questions.

---

# Interview Questions

### Q1. Why does Linux have permissions?

**Answer:**

> Linux uses permissions to control who can read, modify, or execute files and directories, improving security and preventing unauthorized access.

---

### Q2. Why are permissions important in backend development?

**Answer:**

> Backend applications contain sensitive files such as `.env`, logs, and configuration files. Permissions ensure that only authorized users or processes can access or modify them.

---

### Q3. Give an example.

**Answer:**

> A `.env` file stores secrets like database credentials and API keys. Without proper permissions, other users could read or modify those secrets.
