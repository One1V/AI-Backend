# **Read, Write, Execute (r, w, x) Explained**

⭐ **Importance:** **10/10 (Must Know)**

# Every file and folder has 3 basic permissions

```text
r → Read
w → Write
x → Execute
```

These permissions decide **what actions are allowed**.

---

# 1. Read (`r`)

Read means:

> You can **see the contents** of a file.

Example:

Suppose `server.js` contains:

```javascript
console.log("Hello");
```

If you have **Read** permission:

```bash
cat server.js
```

works.

If you don't have Read permission:

```text
Permission denied
```

# 2. Write (`w`)

Write means:

> You can modify the file.

Example:

```bash
nano server.js
```

You change:

```javascript
app.listen(5000)
```

to

```javascript
app.listen(8000)
```

That requires **Write** permission.

Without it:

```text
Permission denied
```

---

# 3. Execute (`x`)

Execute means:

> You can run a file as a program or script.

Example:

```bash
./start.sh
```

If the script has Execute permission:

```text
Server Started
```

Without Execute permission:

```text
Permission denied
```

---

## Backend Example

Suppose you create:

```text
deploy.sh
```

Contents:

```bash
npm install
npm run build
pm2 restart app
```

You can run:

```bash
./deploy.sh
```

only if it has Execute permission.

---

# What About Directories?

Permissions work a little differently on folders.

| Permission | File        | Directory                                                                |
| ---------- | ----------- | ------------------------------------------------------------------------ |
| `r`      | Read file   | List files in the directory                                              |
| `w`      | Modify file | Create, delete, or rename files (with appropriate directory permissions) |
| `x`      | Run file    | Enter/traverse the directory                                             |

# Real Production Example

Suppose your backend has:

```text
uploads/
```

User uploads:

```text
resume.pdf
```

Flow:

```text
Browser

↓

Express

↓

uploads/

↓

Linux checks permissions

↓

Write Allowed?

↓

Yes → Save File

No → Permission denied
```

# Interview Questions

### Q4. Why does a backend application need Write permission?

**Answer:**

To save uploaded files, write logs, create temporary files, or update data on disk.
