## **User, Group, and Others**

⭐ **Importance:** ⭐⭐⭐⭐⭐ (Very Important)

This is the second half of Linux permissions.

---

# Every file belongs to 3 categories

Linux doesn't just ask **"What permission?"**

It also asks:

> **"Permission for whom?"**

Every file has permissions for:

```text
User (u)

Group (g)

Others (o)
```

### 1. User (u)

The **owner** of the file.

---

# 2. Group (g)

A collection of users.

Example:

```text
Backend Team
```

Members:

* Ayush
* Rahul
* Priya

If a file belongs to the **backend** group, everyone in that group can get the permissions assigned to the group.

---

# 3. Others (o)

Everyone who is **not**:

* the owner
* in the group

Example:

Suppose another student logs into the same Linux server.

That student is considered **Others**.

---

# Visual Example

Suppose you have:

```text
server.js
```

Permissions:

```text
User    → Read, Write

Group   → Read

Others  → No Access
```

---

# Real Backend Example

Suppose your project is:

```text
backend/
│
├── server.js
├── .env
└── uploads/
```

### `.env`

You probably want:

| Category | Permission   |
| -------- | ------------ |
| User     | Read & Write |
| Group    | No Access    |
| Others   | No Access    |

Because `.env` contains:

* JWT Secret
* MongoDB URI
* API Keys

Only the owner should access it.

---

### `uploads/`

You might allow:

* Express application → Write files
* Other users → No access

Again, permissions protect your application.

---

# How Linux Displays Permissions

You may see something like:

```text
-rwxr-xr--
```

Don't worry about decoding it yet.

For now, just know it means:

```text
Owner

↓

Group

↓

Others
```

We'll learn the exact format in the next question (`chmod`).

---

# Minimum Required

Remember:

* **User (u)** = Owner of the file.
* **Group (g)** = Users in the same group.
* **Others (o)** = Everyone else.

Permissions (`r`, `w`, `x`) are applied separately to each of these three categories.

---

# Interview Questions

### Q1. What are User, Group, and Others in Linux?

**Answer:**

They are the three categories Linux uses to assign permissions. Every file has separate permissions for the owner (User), users in the same Group, and everyone else (Others).

---

### Q2. Why are they important?

**Answer:**

They allow Linux to control who can read, modify, or execute files, making shared servers secure.

---

### Q3. Give a backend example.

**Answer:**

A `.env` file should normally be readable only by the owner because it contains secrets like database credentials and API keys.
