# **What are `sudo` and `root`?**

⭐ **Importance:** ⭐⭐⭐⭐⭐ (Must Know)

This is one of the most frequently asked Linux interview topics.

---

# What is `root`?

`root` is the **administrator (superuser)** of Linux.

Think of it as:

```text
Windows → Administrator

Linux → root
```

The `root` user has **complete control** over the system.

It can:

* Delete any file
* Install software
* Create users
* Stop services
* Change permissions
* Restart the server

Nothing is restricted for `root`.

---

# What is `sudo`?

`sudo` stands for:

> **S**uper **U**ser **Do**

It means:

> **"Run this command as the root user."**

Example:

Without `sudo`:

```bash
apt install nginx
```

Output:

```text
Permission denied
```

With `sudo`:

```bash
sudo apt install nginx
```

Now Linux temporarily gives you **root privileges** to execute that command.

---

# Why don't we log in as `root` all the time?

Imagine you accidentally type:

```bash
rm -rf /
```

This command attempts to delete files from the root of the filesystem.

If you're running as `root`, it can cause catastrophic damage to the system.

If you're a normal user, Linux blocks many dangerous actions because you don't have sufficient privileges.

---

# Real Backend Example

Suppose you want to install Nginx:

```bash
sudo apt install nginx
```

Why is `sudo` required?

Because installing software changes system directories like:

```text
/usr/
/etc/
/var/
```

Normal users shouldn't be allowed to modify these locations.

---

# Another Backend Example

Your project:

```text
/home/ayush/backend
```

You can edit:

```text
server.js
```

without `sudo` because you own the project.

However, Nginx configuration is stored in:

```text
/etc/nginx/nginx.conf
```

Editing it requires:

```bash
sudo nano /etc/nginx/nginx.conf
```

because it's a system configuration file.

---

# When Do You Use `sudo`?

Common commands:

Install software:

```bash
sudo apt install git
```

Restart Nginx:

```bash
sudo systemctl restart nginx
```

Change ownership:

```bash
sudo chown -R www-data:www-data backend/
```

Edit system configuration:

```bash
sudo nano /etc/nginx/nginx.conf
```

---

# When Should You NOT Use `sudo`?

Inside your own project:

```text
/home/ayush/backend
```

Don't do this:

```bash
sudo npm install
```

unless you specifically need it.

Why?

Files may become owned by `root`.

Later:

```bash
npm install
```

might fail because you no longer own your project files.

This is a very common mistake among beginners.

# Minimum Required

Remember:

* **root** = Administrator of Linux.
* **sudo** = Temporarily execute a command with root privileges.

---

# Interview Questions

### Q1. What is the `root` user?

**Answer:**

The `root` user is the Linux administrator with unrestricted access to the entire system.

---

### Q2. What does `sudo` do?

**Answer:**

`sudo` allows a normal user to execute a command with root privileges.

---

### Q3. Why don't developers always work as `root`?

**Answer:**

Working as `root` increases the risk of accidental system damage. Using a normal user with `sudo` only when needed is safer and follows the principle of least privilege.
