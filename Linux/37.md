# **Why shouldn't you always work as `root`?**

Short Answer

You should **not** always work as `root` because:

* It is unsafe.
* A small mistake can damage the entire system.
* It violates the **Principle of Least Privilege** (give only the permissions needed).

Instead, use a **normal user** and run `sudo` only when necessary.

---

# Real Backend Example 1

Suppose you deploy your project:

```text
/home/ayush/backend
```

Normal work:

```bash
npm install

npm run dev

git pull

nano server.js
```

✅ No `sudo` needed.

---

# Real Backend Example 2

Now you want to restart Nginx.

That affects the entire server.

So you use:

```bash
sudo systemctl restart nginx
```

Only this command gets administrator privileges.

---

# Common Beginner Mistake

Many beginners run everything with `sudo`:

```bash
sudo npm install

sudo npm run dev

sudo git pull
```

Later they get errors like:

```text
Permission denied
```

because all the project files are now owned by `root`.

This is why experienced developers avoid unnecessary `sudo`.

### System-level tasks

```bash
sudo apt update
sudo apt install nginx
sudo systemctl restart nginx
sudo chown -R www-data:www-data /var/www/backend
```

---

### Q2. What is the Principle of Least Privilege?

**Answer:**

It means giving users or applications only the permissions they need to perform their tasks, reducing the risk of accidental or malicious damage.

---

### Q3. Give a backend example.

**Answer:**

Running `npm install` inside your own project should be done as a normal user. Installing Nginx or editing `/etc/nginx/nginx.conf` requires `sudo` because those are system-level operations.
