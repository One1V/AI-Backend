# **How do Linux Permissions Affect Node.js Applications?**

⭐ **Importance:** ⭐⭐⭐⭐⭐ (Extremely Important)

This is where Linux meets **Express.js**.

Until now we've learned:

* `r` (Read)
* `w` (Write)
* `x` (Execute)
* User
* Group
* `chmod`
* `chown`

# Key Idea

A Node.js application is **just another Linux process**.

Whenever it tries to:

* Read a file
* Write a file
* Execute a script

Linux checks permissions first.

If permission is denied, your application gets an error.

---

# Example 1 – Reading `.env`

Suppose your project is:

```text
backend/
│
├── server.js
├── .env
└── package.json
```

Your code:

```javascript
require("dotenv").config();
```

Flow:

```text
Node.js

↓

Read .env

↓

Linux checks Read permission

↓

Allowed?

↓

Yes → Continue

No → Error
```

Without **Read** permission, your app cannot load environment variables.

# Common Errors You'll See

### 1. Cannot read `.env`

Reason:

No Read permission.

---

### 2. Upload failed

Reason:

No Write permission for:

```text
uploads/
```

---

### 3. Log file not created

Reason:

Cannot write to:

```text
logs/
```

---

### 4. Script won't execute

Reason:

No Execute permission.

Fix:

```bash
chmod +x deploy.sh
```

# Interview Questions

### Q1. How do Linux permissions affect Node.js applications?

**Answer:**

Every time a Node.js application reads, writes, or executes a file, Linux checks the file permissions. If the required permission is missing, the operation fails with a "Permission denied" error.

---

### Q2. Give a backend example.

**Answer:**

When Express saves uploaded files to an `uploads` directory, Linux checks whether the process has Write permission. If not, the upload fails.

---

### Q3. Why is `.env` permission important?

**Answer:**

Because Node.js must read the `.env` file to load environment variables such as database credentials, JWT secrets, and API keys.

## 🎯 Quick Revision

* Read → `.env`

* Execute → scripts
* Missing permission = `Permission denied`
