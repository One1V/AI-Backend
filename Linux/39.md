# **How Do File Permissions Affect Deployment?**

First Understand Deployment

Suppose you deploy your backend to an Ubuntu server.

Your project is stored here:

```text
/var/www/backend
```

It contains:

```text
backend/
│
├── server.js
├── .env
├── uploads/
├── package.json
└── logs/
```

Everything looks correct.

But your website doesn't work.

One common reason is **incorrect file permissions**.

# Common Deployment Problems

| Problem                 | Possible Permission Issue      |
| ----------------------- | ------------------------------ |
| `.env` not loading    | Missing Read permission        |
| Uploads fail            | Missing Write permission       |
| Logs not written        | Missing Write permission       |
| Script won't run        | Missing Execute permission     |
| Nginx can't serve files | Wrong permissions or ownership |

---

# Real Interview Scenario

**Interviewer:**

> "Your Express app works locally but not after deployment. What could be wrong?"

A good answer:

> "I would check whether the application has permission to read configuration files, write uploads or logs, and whether the project files have the correct owner and permissions."

This shows production awareness.

---

# Minimum Required

When a deployed backend fails, always consider:

* ✅ File permissions (`chmod`)
* ✅ Ownership (`chown`)
* ✅ Directory permissions
* ✅ Whether the application process can access the required files

Permissions are one of the first things experienced backend engineers check.

---

# Interview Questions

### Q1. How do file permissions affect deployment?

**Answer:**

During deployment, the backend application must read configuration files, write uploads and logs, and sometimes execute scripts. Incorrect permissions or ownership can prevent these operations, causing the application to fail.

---

### Q2. Give an example.

**Answer:**

If the `uploads` directory is not writable by the Node.js process, users won't be able to upload files and the application may return a "Permission denied" error.
