# **Secure a Backend Project Using Linux Permissions**

⭐ **Importance:** ⭐⭐⭐⭐⭐ (Placement + Real World)

---

# Scenario

You have built a MERN backend.

Project:

```text
backend/
│
├── server.js
├── package.json
├── .env
├── uploads/
├── logs/
└── deploy.sh
```

Now you're deploying it to Ubuntu.

Your goal is to make sure everything has the **correct permissions**.

---

# Step 1 — Clone the Project

```bash
git clone https://github.com/username/backend.git

cd backend
```

Nothing special yet.

---

# Step 2 — Install Packages

```bash
npm install
```

Since you own the project, **don't use `sudo`**.

✅ Correct

```bash
npm install
```

❌ Wrong

```bash
sudo npm install
```

Reason:

Using `sudo` may make files owned by `root`.

---

# Step 3 — Create `.env`

Example:

```text
PORT=5000

MONGO_URI=...

JWT_SECRET=...
```

This file contains secrets.

Only you should read or edit it.

So you would typically use restrictive permissions (for example, readable and writable only by the owner).

---

# Step 4 — Uploads Folder

Suppose users upload:

* Resume
* Profile Picture
* PDFs

Express must be able to save files into:

```text
uploads/
```

If the application cannot write here:

```text
Permission denied
```

Uploads fail.

---

# Step 5 — Logs Folder

Your backend writes:

```text
logs/server.log
```

If it cannot write:

No logs are generated.

Debugging becomes difficult.

---

# Step 6 — Deployment Script

Suppose:

```text
deploy.sh
```

contains:

```bash
git pull

npm install

pm2 restart backend
```

Initially:

```bash
./deploy.sh
```

may fail because it isn't executable.

Make it executable:

```bash
chmod +x deploy.sh
```

---

# Step 7 — Start Backend

```bash
npm start
```

or

```bash
pm2 start server.js
```

Node.js is now running.

---

# Step 8 — Reverse Proxy (Later)

Nginx forwards requests:

```text
Internet

↓

Nginx

↓

Express
```

If Nginx cannot access required files because of incorrect permissions or ownership, requests may fail.

We'll configure Nginx in a later module.

---

# Complete Flow

```text
Developer

↓

Git Clone

↓

npm install

↓

Create .env

↓

Correct Permissions

↓

Start Node.js

↓

Nginx

↓

Users
```

# What Linux Concepts Did We Use?

| Concept    | Why?                             |
| ---------- | -------------------------------- |
| Read       | Read`.env`                     |
| Write      | Save uploads                     |
| Execute    | Run`deploy.sh`                 |
| `chmod`  | Set permissions                  |
| `chown`  | Fix ownership when required      |
| `sudo`   | System administration tasks only |
| User/Group | Secure access to files           |

---

# Interview Question

### Q.

During deployment, what Linux concepts do you use?

### Answer

> During deployment I ensure the application has the correct file permissions and ownership. The backend must be able to read configuration files like `.env`, write to directories such as `uploads` and `logs`, execute deployment scripts when needed, and use administrator privileges only for system-level tasks like configuring Nginx or installing packages.---
