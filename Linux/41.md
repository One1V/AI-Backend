
# Module 5 – Question 41

# **What is a Process?**

⭐ **Importance:** ⭐⭐⭐⭐⭐ (Must Know)

This is one of the most fundamental Linux concepts for backend developers.

---

# Definition

A **process** is:

> **A program that is currently running.**

Think of it this way:

* **Program** = Code stored on disk.
* **Process** = That code executing in memory.

---

# Simple Example

Suppose you have:

```text
server.js
```

It is just a file.

When you run:

```bash
node server.js
```

Linux loads it into memory and starts executing it.

Now it becomes a **process**.

---

# Visual Representation

```text
server.js (File)

↓

node server.js

↓

Linux loads it into RAM

↓

Process starts running
```

---

# Real MERN Example

Suppose your backend contains:

```text
backend/
│
├── server.js
├── routes/
├── controllers/
└── package.json
```

You run:

```bash
npm start
```

Internally, npm eventually executes:

```bash
node server.js
```

Linux creates a **Node.js process**.

That process:

* Opens port **5000**
* Waits for HTTP requests
* Talks to MongoDB
* Sends responses

Until you stop it.

---

# Browser Request Flow

```text
Browser

↓

http://localhost:5000

↓

Node.js Process

↓

Express

↓

MongoDB

↓

Response
```

Notice something important:

The browser is **not talking to the file** `server.js`.

It is talking to the **running process** created from `server.js`.

---

# Every Running Application is a Process

When you open:

* Chrome
* VS Code
* Spotify
* Node.js
* MongoDB

Linux creates separate processes for each.

Example:

```text
Chrome        → Process

VS Code       → Process

Node.js       → Process

MongoDB       → Process
```

---

# What Happens When You Press Ctrl + C?

Suppose your server is running:

```bash
npm start
```

Terminal:

```text
Server running on port 5000
```

Now press:

```text
Ctrl + C
```

Linux **terminates the Node.js process**.

Result:

```text
Browser

↓

localhost:5000

↓

No Process Running

↓

Connection Refused
```

That's why your website stops working.

---

# Why is This Important?

Many beginners think:

> "I wrote `server.js`, so my backend exists."

Not exactly.

Your backend exists **only while the Node.js process is running**.

If the process crashes:

* Website goes down.
* API stops responding.
* Users cannot connect.

---

# Real Production Example

On a Linux server:

```bash
node server.js
```

creates a process.

If that process crashes:

❌ Website goes down.

That's why tools like **PM2** and **systemd** exist—they monitor the process and restart it automatically.

We'll learn those later.

---

# Minimum Required

Remember:

* **Program** = File on disk.
* **Process** = Running program in memory.

Your Express backend is a **Node.js process** while it's running.

---

# Interview Questions

### Q1. What is a process?

**Answer:**

A process is a program that is currently executing. It has its own memory, CPU time, and resources managed by the operating system.

---

### Q2. Is `server.js` a process?

**Answer:**

No. `server.js` is a file (a program). It becomes a process only after running it with Node.js.

---

### Q3. Give a backend example.

**Answer:**

When we run `node server.js` or `npm start`, Linux creates a Node.js process that listens for incoming HTTP requests and serves the backend application.

---

# 🧠 Memory Trick

Think of a recipe and a chef.

```text
Recipe Book

↓

Chef starts cooking

↓

Meal being cooked
```

* **Recipe** = Program (`server.js`)
* **Cooking** = Process

A recipe sitting on a shelf does nothing.

A program sitting on disk does nothing until it's running.

# ⭐ Importance

For **MERN + AI Backend Engineer**:

⭐⭐⭐⭐⭐ **Must Know**

Understanding processes is essential because every backend application, database, cache server, and web server you use (Node.js, MongoDB, Redis, Nginx) runs as one or more Linux processes.
