# **`ps`, `top`, and PID (Process ID)**

## First, What is PID?

Every process in Linux gets a **unique number**.

That number is called the **PID (Process ID)**.

Think of it like:

```text
Student → Roll Number

Process → PID
```

Linux uses the PID to identify and manage processes.

---

# Example

Suppose you start your backend:

```bash
node server.js
```

Linux creates:

```text
Node.js Process

PID = 5421
```

Now Linux doesn't say:

> "Stop server.js"

It says:

> "Stop Process 5421."

---

# Why is PID Needed?

Imagine your server is running:

* Node.js
* MongoDB
* Redis
* Nginx
* Chrome

Linux needs a unique way to identify each one.

Example:

```text
Node.js     PID 5421

MongoDB     PID 2100

Redis       PID 1850

Nginx       PID 760
```

---

# The `ps` Command

`ps` stands for:

> **Process Status**

It shows running processes.

Example:

```bash
ps
```

Example output:

```text
PID   TTY      TIME     CMD

5421  pts/0    00:00    node

5500  pts/0    00:00    bash
```

Meaning:

* PID = Process ID
* CMD = Program running

---

# More Useful

Most developers use:

```bash
ps -ef
```

or

```bash
ps aux
```

These show **all running processes** with much more information.

Example:

```text
USER      PID    COMMAND

root      760    nginx

mongodb   2100   mongod

ayush     5421   node server.js
```

---

# Real Backend Example

You SSH into your Ubuntu server.

You don't know whether your backend is running.

Run:

```bash
ps aux
```

Output:

```text
ayush    5421    node server.js
```

Great!

Your backend is running.

---

Suppose nothing appears.

That means:

Your backend process isn't running.

---

# The `top` Command

Unlike `ps`, which gives a snapshot,

`top` shows a **live view**.

Run:

```bash
top
```

You may see something like:

```text
PID   CPU%   MEM%   COMMAND

5421   18%    4%    node

2100    5%    3%    mongod

760     1%    1%    nginx
```

This updates every few seconds.

---

# Why is `top` Useful?

Suppose users complain:

> "The website is very slow."

You run:

```bash
top
```

You see:

```text
Node.js

CPU = 98%
```

Now you know:

The Node.js process is consuming too much CPU.

That's valuable debugging information.

---

# `ps` vs `top`

| `ps`                      | `top`                          |
| --------------------------- | -------------------------------- |
| Snapshot                    | Live monitoring                  |
| Doesn't refresh             | Refreshes continuously           |
| Good for checking processes | Good for monitoring CPU & memory |

---

# Real Production Scenario

Your website stops responding.

First thing many backend engineers check:

```bash
ps aux
```

Is the Node.js process running?

If yes:

Run:

```bash
top
```

Is it using too much CPU or memory?

These two commands are often the first step in diagnosing server problems.

# Interview Questions

### Q1. What is PID?

**Answer:**

PID (Process ID) is a unique number assigned by Linux to every running process.

---

### Q2. What does `ps` do?

**Answer:**

`ps` displays information about running processes.

---

### Q3. What does `top` do?

**Answer:**

`top` provides a live view of running processes, including CPU and memory usage.

---

### Q4. Why is PID important?

**Answer:**

Linux uses the PID to identify and manage processes, such as monitoring or terminating a specific process.
