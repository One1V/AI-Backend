
# Module 5 – Question 49

# **What is `htop`?**

⭐ **Importance:** ⭐⭐⭐⭐☆ (Very Useful)

If `top` is like **Task Manager**, then `htop` is **Task Manager with a better user interface**.

It shows:

* Running processes
* CPU usage
* Memory usage
* PIDs
* Users
* Process tree
* Allows you to kill processes interactively

---

# Why was `htop` created?

Linux already has:

```bash
top
```

But `top`:

* Has a basic text interface.
* Is less intuitive for beginners.
* Requires remembering more keyboard shortcuts.

`htop` improves the experience with a more interactive interface.

---

# Installing `htop`

Ubuntu:

```bash
sudo apt update
sudo apt install htop
```

---

# Running `htop`

```bash
htop
```

You'll see a live dashboard similar to:

```text
CPU0 [||||||||      ] 45%

CPU1 [||||          ] 25%

Memory [||||||||    ] 5.2G / 16G

Swap   [            ] 0G / 2G

PID    USER      CPU%   MEM%   COMMAND

5421   ayush      35      4    node server.js

2100   mongodb     5      3    mongod

760    root        1      1    nginx
```

Unlike `top`, you can easily move around using the keyboard.

---

# Understanding the Columns

Example:

```text
PID    USER     CPU%   MEM%   COMMAND

5421   ayush      28      5    node server.js
```

Meaning:

* **PID** → Process ID
* **USER** → Who started the process
* **CPU%** → CPU being used
* **MEM%** → RAM being used
* **COMMAND** → Running program

---

# Real Backend Example

Suppose your backend becomes slow.

Run:

```bash
htop
```

You notice:

```text
node server.js

CPU = 98%
```

Now you know:

Your Node.js application is consuming almost all the CPU.

This helps you investigate issues like:

* Infinite loops
* Expensive computations
* Too many incoming requests

---

# Another Example

Suppose your server has:

* Node.js
* MongoDB
* Redis
* Nginx

`htop` lets you see all of them at once.

Example:

```text
node server.js

mongod

redis-server

nginx
```

You immediately know which process is consuming the most resources.

---

# Interactive Features

Inside `htop` you can:

* Scroll through processes.
* Search for a process.
* Sort by CPU or memory usage.
* Kill a process.
* View the process tree.

This is much easier than using multiple terminal commands.

# `top` vs `htop`

| `top`                               | `htop`                         |
| ------------------------------------- | -------------------------------- |
| Built into most Linux systems         | Usually needs installation       |
| Basic interface                       | Colorful, interactive interface  |
| Keyboard navigation is less intuitive | Easy navigation                  |
| Live monitoring                       | Live monitoring                  |
| Can manage processes                  | Can manage processes more easily |

# Do Companies Use `htop`?

**Yes.**

Many backend engineers install `htop` on development or production servers because it makes troubleshooting much faster.

However, you should still know `top`, because it is available on almost every Linux system by default.

# Interview Questions

### Q1. What is `htop`?

**Answer:**

`htop` is an interactive Linux process monitoring tool that displays running processes, CPU usage, memory usage, and other system information in a user-friendly interface.

---

### Q2. How is `htop` different from `top`?

**Answer:**

`htop` provides a more interactive and visually organized interface. It supports easier navigation, searching, sorting, and process management, whereas `top` has a simpler text-based interface.

---

### Q3. Give a backend example.

**Answer:**

If a Node.js backend becomes slow, `htop` can help identify whether the Node.js process is consuming excessive CPU or memory, making it easier to diagnose performance issues.
