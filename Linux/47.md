
# Module 5 – **What are Signals? (`SIGTERM`, `SIGKILL`, `SIGINT`)**

Signals are one of the most important Linux concepts for backend developers because they determine **how your Node.js application starts, stops, and shuts down**.

# What is a Signal?

A **signal** is a message sent by Linux to a running process.

It tells the process to perform an action.

Examples:

* Stop
* Pause
* Continue
* Reload configuration
* Interrupt execution

Think of a signal as a notification from the operating system.

---

# How Signals Work

Suppose your Express server is running:

```bash
node server.js
```

Linux creates:

```text
Node.js Process
PID = 5421
```

Now Linux sends a signal.

```text
Linux

↓

Signal

↓

Node.js Process

↓

Process reacts
```

---

# 1. SIGTERM (Signal 15)

This is the **default** signal sent by:

```bash
kill 5421
```

Internally:

```text
kill

↓

SIGTERM

↓

Node.js
```

Meaning:

> **"Please shut down gracefully."**

The application gets time to:

* Finish current requests.
* Close MongoDB connections.
* Save data.
* Flush logs.
* Release resources.

Then it exits.

---

## Example

Suppose a user is downloading a PDF.

Administrator runs:

```bash
kill 5421
```

Node.js can:

```text
Finish response

↓

Close database

↓

Exit
```

This prevents abrupt interruptions.

---

# 2. SIGKILL (Signal 9)

Sent by:

```bash
kill -9 5421
```

Meaning:

> **"Stop immediately."**

Linux does **not** allow the process to clean up.

The process:

* Cannot save data.
* Cannot close files.
* Cannot finish requests.
* Cannot ignore the signal.

It is removed immediately.

---

## Example

Suppose your Node server enters an infinite loop:

```javascript
while(true){

}
```

CPU reaches:

```text
100%
```

You run:

```bash
kill 5421
```

Nothing happens.

Now:

```bash
kill -9 5421
```

Linux immediately terminates the process.

---

# 3. SIGINT (Signal 2)

Sent when you press:

```text
Ctrl + C
```

Example:

```bash
npm start
```

Output:

```text
Server running...
```

Press:

```text
Ctrl + C
```

Linux sends:

```text
SIGINT
```

Node.js usually exits gracefully.

Now:

### SIGTERM

Linux says:

> "Please stop."

### SIGKILL

Linux says:

> "Stop immediately."

# Node.js Can Listen for Signals

A production Node.js app can handle signals:

```javascript
process.on("SIGTERM", () => {
    console.log("Shutting down...");
    server.close();
});
```

Why?

So the application can:

* Stop accepting new requests.
* Finish ongoing requests.
* Close database connections.
* Exit cleanly.

This is called **graceful shutdown**.

You'll often see this in production applications.

---

# Why is This Important?

Imagine you're running:

* Express
* MongoDB
* Redis
* Nginx

When restarting a server, tools like PM2 or `systemd` usually send **SIGTERM** first, giving applications a chance to shut down safely.

Only if the application refuses to stop do they eventually use a forceful termination.

# Interview Questions

### Q1. What is a signal?

**Answer:**

A signal is a software interrupt or notification sent by the operating system to a process, requesting it to perform a specific action such as stopping, interrupting, or reloading.

---

### Q2. What signal does `kill` send?

**Answer:**

By default, `kill` sends **SIGTERM (Signal 15)**, requesting a graceful shutdown.

---

### Q3. What signal does `kill -9` send?

**Answer:**

It sends **SIGKILL (Signal 9)**, which immediately terminates the process without allowing cleanup.

---

### Q4. What happens when you press `Ctrl + C`?

**Answer:**

Linux sends **SIGINT (Signal 2)** to the foreground process, which usually causes it to stop gracefully.

---

### Q5. Why is SIGTERM preferred over SIGKILL?

**Answer:**

Because SIGTERM gives the application an opportunity to finish ongoing work, release resources, close database connections, and shut down cleanly. SIGKILL immediately terminates the process without any cleanup.
