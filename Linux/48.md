# Module 5 – **How do `jobs`, `bg`, and `fg` work?(GREAT  FOR DAILY USE IN VS CODE )**

These commands let you **pause**, **resume**, and **switch** processes between the foreground and background **within the current terminal session**.

---

# First, understand the problem

Suppose you start your Express server:

```bash
node server.js
```

Output:

```text
Server started on port 5000
```

Your terminal is now **occupied** by the Node.js process.

If you type:

```bash
ls
```

Nothing happens because the terminal is busy running your server.

---

# `Ctrl + Z` — Suspend the Process

Instead of stopping the server (`Ctrl + C`), press:

```text
Ctrl + Z
```

Output:

```text
[1]+ Stopped node server.js
```

The process is **paused (suspended)**.

It is **not terminated**.

---

## Difference

| Shortcut     | Effect                        |
| ------------ | ----------------------------- |
| `Ctrl + C` | Stops the process             |
| `Ctrl + Z` | Pauses (suspends) the process |

---

# `jobs`

Now run:

```bash
jobs
```

Output:

```text
[1]+ Stopped node server.js
```

This lists **jobs started from the current terminal**.

Notice:

This is **not** all processes on Linux.

It only shows jobs associated with **this shell session**.

---

# `bg` (Background)

Resume the suspended job in the background:

```bash
bg
```

Output:

```text
[1]+ node server.js &
```

Now:

* Node.js runs again.
* Terminal becomes free.

You can now run:

```bash
ls
pwd
git status
```

while the server keeps running.

---

---

# Real Backend Example

Start your backend:

```bash
npm start
```

Output:

```text
Server Started
```

Now press:

```text
Ctrl + Z
```

Run:

```bash
jobs
```

Output:

```text
[1]+ Stopped npm start
```

Resume:

```bash
bg
```

Continue working:

```bash
git status

nano server.js

ls
```

Later:

```bash
fg
```

Now the Express server returns to the foreground and you can watch incoming requests.

---

# Using Job Numbers

If multiple jobs exist:

```bash
jobs
```

Output:

```text
[1] node server.js

[2] npm run worker
```

Resume job 2:

```bash
bg %2
```

Bring job 1 to foreground:

```bash
fg %1
```

---

# `jobs` vs `ps`

Many beginners confuse these.

### `jobs`

```bash
jobs
```

Shows only:

* Current shell jobs

---

### `ps`

```bash
ps aux
```

Shows:

* All running processes (depending on the options used)

---

# Limitation

These commands only work **while the shell session exists**.

If you disconnect SSH:

```text
SSH Closed

↓

Shell Ends

↓

Jobs Disappear
```

This is why production deployments use:

* PM2 ✅
* `systemd`
* Docker
* Kubernetes

instead of relying on shell job control.

---

# Comparison Table

| Command      | Purpose                    |
| ------------ | -------------------------- |
| `Ctrl + Z` | Suspend current process    |
| `jobs`     | List jobs in current shell |
| `bg`       | Resume job in background   |
| `fg`       | Bring job to foreground    |

---

# Interview Questions

### Q1. What does `jobs` do?

**Answer:**

It lists background and suspended jobs started from the current shell session.

---

### Q2. What does `bg` do?

**Answer:**

It resumes a suspended job and runs it in the background.

---

### Q3. What does `fg` do?

**Answer:**

It brings a background or suspended job back to the foreground.

---

### Q4. What is the difference between `Ctrl + C` and `Ctrl + Z`?

**Answer:**

* `Ctrl + C` sends **SIGINT**, which usually terminates the process.
* `Ctrl + Z` sends **SIGTSTP**, which suspends the process so it can later be resumed with `bg` or `fg`.
