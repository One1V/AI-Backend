# Step 7 — Kill Gracefully

Open another terminal.

Find PID:

```bash
ps aux | grep node
```

Example:

```

```

Run:

```bash

```

Observe:

# Step 8 — Force Kill

Restart:

```bash

```

Now:


The process disappears immediately.

# Step 10 — Simulate SSH

Imagine this terminal is an SSH session.

Run:

```bash
node server.js
```

Now close the terminal.

The process dies.

Reason:

The Node process was attached to that terminal.

This is why production uses PM2 or `systemd`.

# Interview Questions

### Q1. Why does `node server.js` stop after SSH closes?

**Answer:**

Because it runs as a foreground process attached to the SSH terminal. When the SSH session ends, Linux terminates the associated process.

---

### Q2. How do you find the PID of your backend?

**Answer:**

Use:

```bash
ps aux | grep node
```

---

### Q3. How do you monitor CPU usage?

**Answer:**

Use:

```bash
top
```

or

```bash
htop
```

---

### Q4. How do you stop a Node process?

**Answer:**

Find the PID and run:

```bash
kill PID
```

If it doesn't respond:

```bash
kill -9 PID
```

---

### Q5. Why don't companies run `node server.js` directly in production?

**Answer:**

Because the process would stop if the terminal or SSH session ends, and it wouldn't automatically restart if it crashes. Production deployments typically use a process manager such as PM2 or a service manager like `systemd`.
