# Q53 — What are Ports?

A **port** is a logical number used to identify a particular network service or application running on a machine.

If an **IP address identifies the machine**, the **port identifies the service** you want to communicate with.

---

# 2. Why do we need ports?

Imagine your VPS is running:

```text
Nginx
Express
SSH
```

All three use the same IP address:

```text
203.0.113.25
```

How does Linux know which application should receive incoming data?

The **port number** helps identify the destination service.

```text
                   VPS
            203.0.113.25
                  │
        ┌─────────┼─────────┐
        ↓         ↓         ↓
      :22        :80       :5000
       ↓          ↓          ↓
      SSH       Nginx     Express
```

---

# 3. Express Example

You have probably already written:

```javascript
app.listen(5000, () => {
    console.log("Server running");
});
```

This means your Node.js application is listening on **port 5000**.

You can access it locally with:

```text
http://localhost:5000
```

Flow:

```text
Browser
   ↓
localhost
   ↓
Port 5000
   ↓
Node.js / Express
```

# 4. Common ports you should know

For backend interviews, you don't need to memorize hundreds.

Know these:

|  Port | Common use                         |
| ----: | ---------------------------------- |
|    22 | SSH                                |
|    53 | DNS                                |
|    80 | HTTP                               |
|   443 | HTTPS                              |
|  3000 | Common Node/React development port |
|  5000 | Common Express development port    |
| 27017 | MongoDB default                    |
|  6379 | Redis default                      |

**Important:** Ports like 3000 and 5000 aren't special standards. Developers commonly choose them for applications.

# 5. Port range

TCP and UDP ports range from:

```text
0 → 65535
```

They are commonly divided into:

### 0–1023

**Well-known ports**

Examples:

```text
22  → SSH
80  → HTTP
443 → HTTPS
```

### 1024–49151

Registered ports.

### 49152–65535

Dynamic/private ports commonly used for temporary connections.

For your placement preparation, knowing the basic idea is enough.

---

# 6. Port + IP

This is important:

```text
IP address + port
```

together identify a network endpoint.

For example:

```text
192.168.1.10:5000
```

means:

```text
Machine = 192.168.1.10
Service = port 5000
```

# 7. What happens when you open a website?

Suppose you open:

```text
https://example.com
```

Behind the scenes, the browser eventually connects to a server on:

```text
port 443
```

Conceptually:

```text
Browser
   ↓
DNS finds server IP
   ↓
Server IP : 443
   ↓
Nginx
   ↓
Backend
```

For HTTP:

```text
Server IP : 80
```

# 8. Your MERN deployment example

Suppose your VPS has:

```text
Public IP = 203.0.113.25
```

You run:

```text
Express → localhost:5000
Nginx   → :80 / :443
SSH     → :22
```

Your architecture is:

```text
                     Internet
                        ↓
               203.0.113.25
                        │
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
        :22           :80/443        :5000
          ↓             ↓             ↓
        SSH           Nginx        Express
```

In a proper deployment, you generally **don't expose Express's port 5000 publicly**.

Instead:

```text
Internet
   ↓
:443
   ↓
Nginx
   ↓
localhost:5000
   ↓
Express
```

That's an important production concept.

# 9. How do you check which ports are being used?

On Linux, you'll commonly use:

```bash
ss -tulpn
```

You might see:

```text
LISTEN  0  511  0.0.0.0:80
LISTEN  0  128  0.0.0.0:22
LISTEN  0  511  127.0.0.1:5000
```

This tells you that services are listening on those ports.

Later in this module you'll learn `ss`, `lsof`, and `fuser` in more detail.

# 10. Very common backend problem

Suppose you start Express:

```bash
node server.js
```

and get:

```text
Error: listen EADDRINUSE: address already in use :::5000
```

It means:

> **Something is already using port 5000.**

You can investigate with:

```bash
sudo ss -ltnp | grep :5000
```

or:

```bash
sudo lsof -i :5000
```

You'll learn this properly in **Q56–57**.

# 🧠 Interview Questions

### Q1. What is a port?

> A port is a logical communication endpoint used to identify a particular network service or application on a machine.

### Q2. Difference between IP and port?

> An IP address identifies the network interface/device, while a port identifies the service or application communicating through that address.

### Q3. What port does SSH normally use?

> **22**

### Q4. What ports do HTTP and HTTPS use?

> **80 and 443**, respectively.

### Q5. What happens if two applications try to listen on the same port?

Usually, the second application cannot bind to that same IP/port combination and you'll get an **address already in use** error.
