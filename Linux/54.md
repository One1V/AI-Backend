# Q54 — What is a Socket?

A **socket** is an endpoint used by two programs to communicate over a network.

The easiest way to understand it is:

> **IP address + Port + Protocol = Network endpoint used for communication**

A socket is what applications use to **send and receive network data**.

---

# 2. Your Express server

Suppose you write:

```javascript
app.listen(5000);
```

Node.js asks the operating system to create a listening network endpoint.

Conceptually:

```text
Node.js
   ↓
Operating System
   ↓
Create listening socket
   ↓
127.0.0.1:5000
```

Now Express is waiting for incoming connections.

---

# 3. Browser connects to Express

You open:

```text
http://localhost:5000
```

The flow is roughly:

```text
Browser
   ↓
Create client-side connection
   ↓
127.0.0.1:5000
   ↓
Express listening socket
   ↓
HTTP request
   ↓
HTTP response
```

The socket provides the communication channel through which the data travels.

---

# 4. Listening socket vs connection

This distinction is useful.

Suppose your Express server is listening on:

```text
127.0.0.1:5000
```

There is a **listening socket** waiting for connections.

When a browser connects:

```text
Browser
   ↓
Connect
   ↓
Listening socket
   ↓
New connection
```

The server can then communicate with that particular client.

So conceptually:

```text
Server
│
└── Listening socket :5000
       │
       ├── Client A connection
       ├── Client B connection
       └── Client C connection
```

That's how one server can handle many clients.

---

# 5. TCP socket

For most web applications, you'll encounter **TCP**.

TCP provides reliable, ordered communication.

For example:

```text
Browser
   ↓
TCP connection
   ↓
Nginx
```

TCP makes sure data is delivered reliably and in order, subject to connection/network conditions.

HTTP/1.1 and HTTP/2 commonly run over TCP, while HTTP/3 uses QUIC over UDP.

For your current level, remember:

> **Traditional HTTP/HTTPS commonly uses TCP.**

---

# 6. UDP sockets

UDP is another transport protocol.

Unlike TCP, UDP doesn't establish the same kind of connection-oriented reliable stream.

It's useful when low latency is more important than guaranteed delivery, depending on the application.

Examples include:

* DNS queries
* Online games
* Real-time media
* QUIC/HTTP/3

You don't need to go deeply into UDP yet.

---

# 7. Socket vs Port

This is where students often get confused.

### Port

A port is a **number**:

```text
5000
```

### Socket

A socket is an **OS-managed communication endpoint** associated with network addressing and a transport protocol.

For example:

```text
TCP
127.0.0.1
5000
```

is associated with a TCP socket endpoint.

Think:

```text
Port = Door number

Socket = Actual communication endpoint/door used by the application
```

---

# 8. Client and server sockets

Suppose:

```text
Browser → Express
```

The browser uses a client-side socket.

Express has a listening socket.

Conceptually:

```text
CLIENT                              SERVER

Browser                             Express
  │                                    │
  │ client socket                      │ listening socket
  │                                    │
  └────────── TCP connection ──────────┘
```

Once connected, both sides can send and receive data.

---

# 9. Why this matters for backend development

Suppose your Express application suddenly gives:

```text
EADDRINUSE
```

and says:

```text
Port 5000 already in use
```

This means another process is already listening on that address/port combination.

You can investigate:

```bash
ss -ltnp | grep :5000
```

or:

```bash
sudo lsof -i :5000
```

You are essentially asking Linux:

> "Which process owns/listens on this network endpoint?"

# 10. Your complete deployment example

Now combine what we've learned:

```text
                    Internet
                       ↓
                    Browser
                       ↓
                     DNS
                       ↓
                 Public IP
                       ↓
                 TCP connection
                       ↓
                    Nginx
                 :80 / :443
                       ↓
             localhost:5000
                       ↓
              Express / Node.js
                       ↓
                   MongoDB
```

Behind the scenes, sockets are involved in these network communications.

Linux manages the underlying networking resources and processes.

---

# 🧠 Interview Answer

If asked:

> **"What is a socket?"**

Say:

> **"A socket is a communication endpoint used by an application to send and receive data over a network. It is associated with an IP address, port, and transport protocol such as TCP or UDP. For example, an Express server listening on port 5000 uses a network socket to accept client connections."**

That's a good junior backend-level answer.
