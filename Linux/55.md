
# Q55 — How do `ping`, `curl`, and `wget` work?

These are **network troubleshooting and communication tools** you'll use frequently on a Linux server.

The easiest way to remember them:

```text
ping → "Can I reach this machine?"
curl → "Can I communicate with this URL/API?"
wget → "Can I download this resource?"
```

---

# 1. `ping`

`ping` checks whether another host is reachable over the network and measures round-trip time.

Example:

```bash
ping google.com
```

You'll see something like:

```text
64 bytes from ...: time=20 ms
64 bytes from ...: time=19 ms
```

Meaning your machine is receiving responses.

### What happens?

Conceptually:

```text
Your machine
     ↓
ICMP Echo Request
     ↓
Google's server
     ↓
ICMP Echo Reply
     ↓
Your machine
```

`ping` primarily uses **ICMP**, not TCP.

---

## Example with your VPS

Suppose your VPS has:

```text
203.0.113.25
```

Run:

```bash
ping 203.0.113.25
```

If it responds:

```text
64 bytes from 203.0.113.25: time=30 ms
```

your machine is receiving ICMP responses from that address.

### Important

A failed `ping` **doesn't necessarily mean the server is down**.

A firewall may block ICMP while HTTP/HTTPS and SSH continue working.

So:

```text
ping fails
```

doesn't automatically mean:

```text
server is dead
```

---

# 2. `curl`

`curl` is extremely important for backend developers.

It allows you to make requests to URLs and inspect responses.

For example:

```bash
curl http://localhost:5000
```

If your Express server has:

```javascript
app.get("/", (req, res) => {
    res.send("Hello");
});
```

you'll get:

```text
Hello
```

Flow:

```text
curl
 ↓
localhost:5000
 ↓
Express
 ↓
HTTP response
 ↓
curl displays response
```

---

# 3. `curl` and APIs

Suppose your backend has:

```text
GET /api/users
```

You can test it without opening a browser:

```bash
curl http://localhost:5000/api/users
```

Maybe the response is:

```json
[
  {
    "name": "Ayush"
  }
]
```

This is extremely useful when debugging a backend.

---

# 4. Testing POST requests

You can even send data.

For example:

```bash
curl -X POST http://localhost:5000/api/users \
-H "Content-Type: application/json" \
-d '{"name":"Ayush"}'
```

Conceptually:

```text
curl
 ↓
POST request
 ↓
Express
 ↓
req.body
 ↓
Controller
 ↓
Database
 ↓
Response
```

So `curl` is basically a **command-line HTTP client**.

---

# 5. `curl -I`

You can request only the response headers:

```bash
curl -I https://example.com
```

You might see:

```text
HTTP/2 200
content-type: text/html
server: ...
```

This is useful for checking:

* HTTP status
* redirects
* content type
* server headers
* caching headers

---

# 6. `curl -v`

For deeper debugging:

```bash
curl -v http://localhost:5000
```

`-v` means **verbose**.

It gives you more information about the connection and request/response.

Useful when debugging:

```text
Browser works ❓
API doesn't work ❓
Nginx configuration ❓
HTTPS problem ❓
```

---

# 7. `wget`

`wget` is primarily used for **downloading files/resources** from the network.

For example:

```bash
wget https://example.com/file.zip
```

It downloads the file to your current directory.

You can think:

```text
curl → communicate with URLs/APIs
wget → download resources
```

There is overlap—`curl` can download files too—but their common usage differs.

---

# 8. Real VPS example

Suppose you've deployed:

```text
Linux VPS
    ↓
Nginx :443
    ↓
Express :5000
```

You can test each layer.

### Test Express directly

From inside the VPS:

```bash
curl http://localhost:5000
```

If it works:

```text
Express ✅
```

### Test Nginx

```bash
curl http://localhost
```

If that works:

```text
Nginx ✅
```

### Test your domain

```bash
curl https://yourdomain.com
```

If that works:

```text
DNS + Nginx + HTTPS + application ✅
```

This is **much better than blindly opening the website and guessing what's broken.**

---

# 9. Debugging example

Suppose your website isn't working.

You test:

```bash
curl http://localhost:5000
```

Result:

```text
Express response
```

Therefore:

```text
Express ✅
```

Then:

```bash
curl http://localhost
```

Result:

```text
Nginx response
```

Therefore:

```text
Nginx ✅
```

Then:

```bash
curl https://example.com
```

Fails.

Now you know the problem is probably **above the application layer**, such as:

```text
DNS
HTTPS
firewall/network configuration
Nginx server configuration
```

This is how these tools become useful in real backend deployment.

---

# 10. Comparison

| Command  | Main purpose                                     |
| -------- | ------------------------------------------------ |
| `ping` | Test network reachability using ICMP             |
| `curl` | Make/test network requests, especially HTTP APIs |
| `wget` | Download files/resources                         |

Remember:

```text
ping
 ↓
"Can I reach it?"

curl
 ↓
"Can I talk to its API/web server?"

wget
 ↓
"Can I download this?"
```

---

# 🧠 Interview Questions

### "What is ping?"

> `ping` is a network diagnostic tool that uses ICMP echo requests/replies to test reachability and measure round-trip time.

### "What is curl?"

> `curl` is a command-line tool for transferring data and making requests to URLs. It's commonly used by backend developers to test HTTP APIs.

### "curl vs wget?"

> `curl` is commonly used for interacting with APIs and inspecting HTTP responses, while `wget` is commonly used for downloading files. Both can perform some overlapping tasks.
