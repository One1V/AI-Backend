
# Q56 — How do `netstat` and `ss` help debug networking?

When you're running a backend on Linux, one common question is:

> **"Which process is listening on this port?"**

For example, your Express app should run on:

```text
localhost:5000
```

but you get:

```text
EADDRINUSE: address already in use
```

You need to find **what is using port 5000**.

That's where `ss` and `netstat` come in.

---

# 1. What is `ss`?

`ss` stands for **socket statistics**.

It shows information about network sockets and connections.

It's the modern tool you should prefer on Linux.

Try:

```bash
ss
```

You can get more useful information with:

```bash
ss -tuln
```

Let's understand it:

```text
-t → TCP
-u → UDP
-l → listening
-n → don't resolve names; show numbers
```

So:

```bash
ss -tuln
```

basically means:

> **Show TCP/UDP sockets that are listening, using numeric addresses/ports.**

---

# 2. Real Express example

Suppose you start:

```bash
node server.js
```

and your application has:

```javascript
app.listen(5000);
```

Run:

```bash
ss -tuln
```

You might see:

```text
Netid  State   Local Address:Port
tcp    LISTEN  127.0.0.1:5000
```

This tells you:

```text
TCP
 ↓
LISTENING
 ↓
127.0.0.1
 ↓
Port 5000
```

So something is listening on port 5000.

---

# 3. Finding the actual process

Use:

```bash
sudo ss -tulpn
```

The extra:

```text
-p → show process information
```

You might see:

```text
tcp LISTEN 0 511 127.0.0.1:5000
users:(("node",pid=12345,fd=20))
```

Now you know:

```text
Port 5000
    ↓
Node.js
    ↓
PID 12345
```

That's extremely useful.

---

# 4. Real debugging scenario

You run:

```bash
node server.js
```

and get:

```text
Error: listen EADDRINUSE: address already in use :::5000
```

You don't know what's using it.

Run:

```bash
sudo ss -ltnp | grep :5000
```

You might get:

```text
LISTEN 0 511 0.0.0.0:5000
users:(("node",pid=12345,fd=20))
```

Now:

```text
Process = node
PID = 12345
Port = 5000
```

You can inspect it:

```bash
ps -p 12345 -f
```

And if it's an old process you don't need:

```bash
kill 12345
```

Then start your new server.

---

# 5. What is `netstat`?

`netstat` is another tool for viewing network connections, routing information, and listening ports.

A common command is:

```bash
netstat -tulpn
```

It gives information similar to:

```text
Proto  Local Address   PID/Program
tcp    0.0.0.0:5000    12345/node
tcp    0.0.0.0:80      1000/nginx
```

However, on many modern Linux distributions, `netstat` isn't installed by default.

`ss` is generally preferred.

---

# 6. `ss` vs `netstat`

|                       | `ss`            | `netstat`         |
| --------------------- | ----------------- | ------------------- |
| Modern Linux          | ✅ Preferred      | Older               |
| Shows sockets         | ✅                | ✅                  |
| Shows listening ports | ✅                | ✅                  |
| Shows processes       | ✅ with`-p`     | ✅ with`-p`       |
| May need installation | Usually available | Often not installed |

For your Linux learning:

> **Learn `ss` properly. Know that `netstat` is the older alternative.**

You don't need to spend hours memorizing `netstat`.

---

# 7. Check a specific port

This is one of the most useful commands to remember:

```bash
sudo ss -ltnp | grep :5000
```

You're essentially asking:

> "Show me the TCP process listening on port 5000."

For example:

```text
127.0.0.1:5000
```

means it's listening only on localhost.

Whereas:

```text
0.0.0.0:5000
```

means it's listening on all IPv4 interfaces.

That's an important distinction.

---

# 8. Your Nginx + Express deployment

Suppose your VPS has:

```text
Nginx → :80
Express → 127.0.0.1:5000
SSH → :22
```

Run:

```bash
sudo ss -ltnp
```

You might see:

```text
LISTEN 0 511 0.0.0.0:22
LISTEN 0 511 0.0.0.0:80
LISTEN 0 511 127.0.0.1:5000
```

You can interpret it as:

```text
:22
 ↓
SSH

:80
 ↓
Nginx

127.0.0.1:5000
 ↓
Express
```

So your architecture is:

```text
Internet
   ↓
Port 80
   ↓
Nginx
   ↓
127.0.0.1:5000
   ↓
Express
```

This is exactly the kind of thing you'll use when deploying your MERN projects without Render/Vercel.

---

# 9. Established connections vs listening

`ss` can show more than just listening sockets.

For example:

```bash
ss -tan
```

shows TCP sockets, including connections.

You may see states such as:

```text
LISTEN
ESTAB
TIME-WAIT
```

For your current level:

* **LISTEN** → waiting for connections
* **ESTAB** → established connection
* **TIME-WAIT** → connection recently closed; TCP is handling cleanup/timing

You don't need to memorize every TCP state yet.

---

# 🧠 Interview answer

If asked:

> **"How do you check which process is using port 5000 on Linux?"**

A strong practical answer:

```bash
sudo ss -ltnp | grep :5000
```

Then explain:

> "`ss` displays socket information. With `-l` I see listening sockets, `-t` filters TCP, `-n` keeps addresses numeric, and `-p` shows the associated process."

If asked:

> **"What is netstat?"**

Say:

> "`netstat` is a traditional Linux networking utility used to inspect connections, listening ports, routing information, and network statistics. `ss` is its more modern replacement on Linux."
