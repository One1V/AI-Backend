
# Q57 — How do `lsof` and `fuser` identify port usage?

Suppose you're running your Express backend:

```bash
node server.js
```

and you get:

```text
EADDRINUSE: address already in use :::5000
```

You know **port 5000 is occupied**, but you need to know **which process is using it**.

Two useful Linux commands are:

```text
lsof
fuser
```

---

# 1. `lsof`

`lsof` means:

> **List Open Files**

In Linux, many resources—including network sockets—are represented through file descriptors.

So `lsof` can show which process has a particular network resource open.

For port 5000:

```bash
sudo lsof -i :5000
```

You might get:

```text
COMMAND   PID   USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
node    12345  ayush   20u  IPv6 ...          TCP *:5000 (LISTEN)
```

The important information is:

```text
COMMAND → node
PID     → 12345
USER    → ayush
PORT    → 5000
```

So:

```text
Port 5000
    ↓
Node.js
    ↓
PID 12345
```

---

# 2. Why is this useful?

Suppose you forgot that you already started your Express server.

You run:

```bash
node server.js
```

and receive:

```text
EADDRINUSE
```

Instead of randomly killing processes, do:

```bash
sudo lsof -i :5000
```

You discover:

```text
node 12345 ayush ... TCP *:5000 (LISTEN)
```

Now you know exactly what's happening.

You can inspect it:

```bash
ps -p 12345 -f
```

And if it's an old process you don't need:

```bash
kill 12345
```

Then start your server again.

---

# 3. `fuser`

`fuser` is another command that can tell you which processes are using a resource.

For port 5000:

```bash
sudo fuser 5000/tcp
```

You might see:

```text
5000/tcp: 12345
```

Meaning:

```text
Port 5000
    ↓
PID 12345
```

You can get more information with:

```bash
sudo fuser -v 5000/tcp
```

You might see:

```text
USER     PID ACCESS COMMAND
ayush  12345  F.... node
```

---

# 4. `lsof` vs `fuser`

Both can identify processes using ports.

But their style is different.

### `lsof`

More detailed:

```bash
sudo lsof -i :5000
```

Gives information about:

* Process
* PID
* User
* File descriptor
* Network protocol
* Address
* Port
* Connection state

### `fuser`

More direct:

```bash
sudo fuser 5000/tcp
```

Basically:

> "Which process is using this resource?"

---

# 5. Comparison with `ss`

You've now learned three ways to investigate a port:

```text
ss
lsof
fuser
```

### `ss`

Good for understanding sockets/network state:

```bash
sudo ss -ltnp | grep :5000
```

### `lsof`

Good for detailed process/resource information:

```bash
sudo lsof -i :5000
```

### `fuser`

Good for quickly identifying the PID:

```bash
sudo fuser 5000/tcp
```

---

# 6. Real Express debugging

Imagine your VPS has:

```text
Linux VPS
│
├── Nginx → :80
│
├── Express → :5000
│
└── SSH → :22
```

You accidentally start Express twice:

```text
Process 1
Node.js → :5000

Process 2
Node.js → :5000 ❌
```

The second process fails because the port is already occupied.

You run:

```bash
sudo lsof -i :5000
```

and discover:

```text
node  15320  ayush  ... TCP 127.0.0.1:5000 (LISTEN)
```

You now know:

```text
PID = 15320
```

Then:

```bash
kill 15320
```

Now port 5000 may become available.

---

# 7. Don't blindly use `kill -9`

You could technically do:

```bash
kill -9 15320
```

but don't make that your first response.

Prefer:

```bash
kill 15320
```

because the default `SIGTERM` gives the application an opportunity to shut down cleanly.

Only use `kill -9` when necessary—for example, if the process refuses to terminate.

This connects directly to **Q46 and Q47** that you already learned.

---

# 8. Important commands to remember

For your placement preparation, you don't need to memorize everything.

Remember these three:

```bash
sudo ss -ltnp | grep :5000
```

```bash
sudo lsof -i :5000
```

```bash
sudo fuser 5000/tcp
```

They all help answer:

> **"Who is using port 5000?"**

---

# 🧠 Interview Question

### "How would you find which process is using port 5000?"

You can answer:

> "I can use `ss`, `lsof`, or `fuser`. For example, `sudo lsof -i :5000` shows the process and PID using that port. Alternatively, `sudo ss -ltnp | grep :5000` shows the listening socket and associated process."

That's a very practical Linux/backend answer.
