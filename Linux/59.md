
# Q59 — How does SSH work?

**SSH = Secure Shell.**

SSH allows you to securely connect to and control a remote machine through a terminal.

This is **extremely important for your goal of deploying MERN applications without Vercel/Render**, because when you rent a VPS, you commonly manage it through SSH.

---

## 1. Real example

Suppose you rent a Linux VPS.

It has:

```text
Public IP:
203.0.113.25
```

Your laptop is here:

```text
Your Laptop
```

You want to access the VPS.

You run:

```bash
ssh ayush@203.0.113.25
```

The flow is:

```text
Your Laptop
     │
     │ SSH
     ▼
Internet
     │
     ▼
203.0.113.25:22
     │
     ▼
Linux VPS
     │
     ▼
ayush's shell
```

Now the terminal you're using is effectively interacting with the remote Linux machine.

---

# 2. Why port 22?

SSH normally uses:

```text
Port 22
```

So:

```text
ssh ayush@203.0.113.25
```

is conceptually connecting to:

```text
203.0.113.25:22
```

Remember your previous questions:

```text
IP   → Which machine?
Port → Which service?
```

Therefore:

```text
203.0.113.25:22
       ↓
SSH service on the VPS
```

---

# 3. What happens when you run SSH?

You type:

```bash
ssh ayush@203.0.113.25
```

Conceptually:

```text
SSH Client
    ↓
Network connection
    ↓
VPS port 22
    ↓
SSH Server
    ↓
Authentication
    ↓
Encrypted session
    ↓
Remote shell
```

Once authenticated, you might see:

```text
ayush@server:~$
```

Now:

```bash
pwd
```

might return:

```text
/home/ayush
```

But this is the **VPS's filesystem**, not your laptop's.

---

# 4. Your laptop vs VPS

This distinction is extremely important.

Before SSH:

```text
Your Laptop
/home/ayush/
```

After:

```bash
ssh ayush@203.0.113.25
```

you're working on:

```text
Linux VPS
/home/ayush/
```

So if you run:

```bash
ls
```

you're seeing files on the VPS.

---

# 5. How does SSH authenticate you?

There are two common methods:

### Password authentication

You might connect:

```bash
ssh ayush@203.0.113.25
```

and receive:

```text
password:
```

You enter your password.

---

### SSH key authentication

This is more common and preferred for server administration.

You have:

```text
Your Laptop
├── Private key 🔐
└── Public key
```

The server stores your public key:

```text
VPS
└── ~/.ssh/authorized_keys
```

Conceptually:

```text
Your Laptop
    │
    │ proves possession of private key
    ▼
SSH Server
    │
    ▼
authorized_keys
    │
    ▼
Authentication successful
```

The **private key should remain secret**.

Never upload your private SSH key to GitHub.

---

# 6. Why SSH keys are useful

Suppose you deploy your backend to a VPS.

You don't want to type a password every time.

You configure SSH keys:

```text
Laptop
  │
  │ private key
  ▼
VPS
  │
  │ public key
  ▼
authorized_keys
```

Then:

```bash
ssh ayush@203.0.113.25
```

can authenticate using the key.

---

# 7. SSH is encrypted

SSH provides an encrypted communication channel.

Without encryption, someone on the network could potentially observe sensitive information.

SSH protects the session so you can safely perform server administration over an untrusted network.

For example:

```text
You type:

cat .env
```

The command and resulting data travel through the encrypted SSH session.

This is where everything you've learned starts coming together.

You have:

---

# 9. SSH doesn't mean "remote desktop"

SSH normally gives you a **remote command-line session**.

For example:

```bash
ssh ayush@203.0.113.25
```

Then:

```bash
cd backend
ls
git pull
npm install
sudo systemctl restart myapp
```

You're controlling the remote Linux server through the terminal.

---

# 10. What if SSH connection fails?

You might get:

```text
ssh: connect to host 203.0.113.25 port 22: Connection refused
```

Possible causes include:

```text
SSH service not running
Port 22 not listening
Firewall blocking port 22
Wrong IP
Network/security-group configuration
```

You can investigate on the server with:

```bash
ss -ltnp | grep :22
```

Notice how Q56 comes back into use.

# 11. SSH + Nginx + Express

Your complete architecture is becoming:

```text
                    INTERNET
                       │
           ┌───────────┴───────────┐
           │                       │
        Browser                  Your Laptop
           │                       │
           │ HTTPS                 │ SSH
           ▼                       ▼
       Nginx :443              VPS :22
           │
           ▼
   Express :5000
           │
           ▼
       MongoDB
```

There are **two completely different types of traffic**:

```text
Browser → Nginx → Express
        HTTP/HTTPS

Laptop → SSH → VPS
        Remote administration
```

This distinction is important in interviews.

# 🧠 Interview Questions

### "What is SSH?"

> **SSH, or Secure Shell, is a secure protocol used to remotely access and administer a machine over an encrypted connection.**

### "What port does SSH use?"

> **Port 22 by default.**

### "How do you connect to a remote Linux server?"

```bash
ssh username@server-ip
```

### "What is the difference between password and SSH-key authentication?"

> **Password authentication uses a password, while key-based authentication uses a public/private key pair. The private key remains with the client and the public key is stored on the server, typically in `authorized_keys`.**

### "Why is SSH important for backend developers?"

> **It allows me to remotely manage Linux servers, deploy applications, inspect logs, configure services, and troubleshoot production systems.**
