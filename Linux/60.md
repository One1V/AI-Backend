
# Q60 — Mini Project: Connect to a Remote Linux Server Using SSH

This is your **Module 6 mini-project**.

The goal isn't just to run `ssh` once. You should understand what is happening from **your laptop → internet → VPS → Linux shell**.

---

# 🎯 Goal

By the end, you should be able to:

```text
Your Laptop
     │
     │ SSH
     ▼
Internet
     │
     ▼
Linux VPS
     │
     ├── Create files
     ├── Install packages
     ├── Run commands
     └── Run your backend
```

This is the foundation for deploying your MERN applications without Render/Vercel.

---

# Step 1 — Get a Linux VPS

You need a VPS with a Linux distribution such as Ubuntu.

You will receive something like:

```text
Public IP: 203.0.113.25
Username: ubuntu
```

The actual IP and username will be provided by your VPS provider.

**Don't post your real server IP, password, or private SSH key publicly.**

---

# Step 2 — Check SSH on your laptop

Since you're already using Linux, run:

```bash
ssh -V
```

You should get something similar to:

```text
OpenSSH_9.x
```

That means your SSH client is installed.

---

# Step 3 — Connect to the VPS

Suppose:

```text
Username = ubuntu
Server IP = 203.0.113.25
```

Run:

```bash
ssh ubuntu@203.0.113.25
```

You may see:

```text
The authenticity of host '203.0.113.25' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Type:

```bash
yes
```

Then authenticate using the method configured for your VPS.

---

# Step 4 — Notice the prompt change

Before SSH:

```text
ayush@ayush-lenovo:~$
```

After SSH:

```text
ubuntu@server:~$
```

This is important.

You are no longer executing commands on your laptop.

You're now operating on the **remote VPS**.

---

# Step 5 — Verify the remote machine

Run:

```bash
hostname
```

Then:

```bash
pwd
```

Then:

```bash
whoami
```

Then:

```bash
uname -a
```

You'll get information about the remote Linux system.

For example:

```text
whoami
→ ubuntu
```

This confirms which user you're logged in as.

---

# Step 6 — Create a test project

Run:

```bash
mkdir ~/ssh-test
cd ~/ssh-test
```

Create a file:

```bash
touch hello.txt
```

Check it:

```bash
ls -l
```

You should see:

```text
hello.txt
```

Put something inside:

```bash
echo "Hello from my VPS" > hello.txt
```

Then:

```bash
cat hello.txt
```

You should see:

```text
Hello from my VPS
```

---

# Step 7 — Understand what just happened

Your laptop:

```text
Laptop
```

sent commands through:

```text
SSH
```

to:

```text
Linux VPS
```

Linux executed them:

```text
mkdir
touch
echo
cat
```

So:

```text
Laptop
   │
   │ SSH
   ▼
Linux VPS
   │
   ├── mkdir
   ├── touch
   ├── echo
   └── cat
```

This is the foundation of remote server administration.

---

# Step 8 — Test networking

On the VPS run:

```bash
ss -ltn
```

You should see some listening services.

You can also check SSH:

```bash
ss -ltn | grep :22
```

If SSH is listening on port 22, you'll see an entry involving:

```text
:22
```

---

# Step 9 — Run a simple Node server

If Node.js is installed on your VPS, create:

```bash
nano server.js
```

Put:

```javascript
const http = require("http");

const server = http.createServer((req, res) => {
    res.end("Hello from my Linux VPS!");
});

server.listen(5000, () => {
    console.log("Server running on port 5000");
});
```

Save the file and run:

```bash
node server.js
```

You should see:

```text
Server running on port 5000
```

Now verify from the VPS:

```bash
curl http://localhost:5000
```

You should get:

```text
Hello from my Linux VPS!
```

---

# Step 10 — Understand the architecture

You've now created:

```text
                  YOUR LAPTOP
                       │
                       │ SSH :22
                       ▼
                  Linux VPS
                       │
                       │
                 Node.js :5000
                       │
                       ▼
                  Express/App
```

Notice something important:

**SSH and your Node application use different ports.**

```text
:22   → SSH
:5000 → Node
```

---

# Step 11 — Disconnect

Type:

```bash
exit
```

You'll return to:

```text
ayush@ayush-lenovo:~$
```

You're back on your laptop.

---

# Step 12 — The important experiment

Now reconnect:

```bash
ssh ubuntu@203.0.113.25
```

Check:

```bash
cd ~/ssh-test
ls
```

You'll still see:

```text
hello.txt
```

Why?

Because the file was created on the **VPS**, not your laptop.

# 🧠 Your Q60 interview answer

If asked:

> **"How would you connect to a remote Linux server?"**

Say:

```bash
ssh username@server-ip
```

Then explain:

> "SSH establishes an encrypted remote shell session, normally through port 22. Once authenticated, I can manage the remote Linux server, deploy applications, inspect logs, configure services, and troubleshoot the system."

That's exactly the level you should be aiming for.
