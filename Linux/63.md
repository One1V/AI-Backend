# Q63 — How do packages get installed?

When you run:

```bash
sudo apt install nginx
```

it may look like one command, but Linux performs several steps behind the scenes.

The basic flow is:

```text
apt install nginx
        ↓
Find package
        ↓
Check dependencies
        ↓
Download packages
        ↓
Verify packages
        ↓
Unpack
        ↓
Configure
        ↓
Install
```

Let's understand it.

---

## 1. You request a package

You run:

```bash
sudo apt install nginx
```

APT receives:

```text
Package requested = nginx
```

APT then checks its package information to determine which version is available.

---

# 2. APT checks dependencies

Nginx may require other packages to work correctly.

Conceptually:

```text
nginx
 ├── dependency A
 ├── dependency B
 └── dependency C
```

APT automatically resolves these dependencies.

That's one of the biggest advantages of using a package manager.

Instead of manually finding everything, you tell APT:

```bash
sudo apt install nginx
```

and it handles the dependency chain.

---

# 3. APT finds the repository

Your Ubuntu system has configured package repositories.

Conceptually:

```text
Your VPS
   │
   │ apt
   ▼
Ubuntu Repository
   │
   ▼
nginx package
```

The repository contains package information and package files.

---

# 4. Packages are downloaded

APT downloads the required package files.

For Debian/Ubuntu systems, packages commonly have:

```text
.deb
```

extension.

For example:

```text
nginx_....deb
```

You don't normally need to manually download `.deb` files when using APT.

APT does it for you.

---

# 5. Dependencies are downloaded too

Suppose:

```text
nginx
 ↓
requires package A
 ↓
requires package B
```

APT can download those packages as well.

So:

```text
sudo apt install nginx
```

could result in:

```text
nginx
package A
package B
package C
```

being installed.

---

# 6. Package verification

APT/package-management infrastructure performs integrity/authenticity checks using repository metadata and package signatures/checksums.

The purpose is to help ensure that the packages you're installing correspond to trusted repository content and haven't been improperly modified.

You don't need to memorize the cryptographic implementation for placement interviews.

Just understand:

> **Package installation isn't simply "download a random file and execute it."**

---

# 7. Unpacking

After downloading the `.deb` package, the package system **unpacks** its contents into the appropriate locations.

For example, software may place files under directories such as:

```text
/etc
/usr
/var
```

depending on the package.

This connects directly to your Linux filesystem knowledge.

---

# 8. Configuration

Packages can also have installation/configuration scripts.

For example, installing Nginx may create configuration files and system integration.

You might end up with things such as:

```text
/etc/nginx/
```

and a service managed through:

```text
systemd
```

So installing a package isn't always just copying one executable.

---

# 9. Package database

Linux keeps track of installed packages.

On Debian/Ubuntu systems, the underlying package database is managed by **dpkg**.

You can see installed packages with:

```bash
dpkg -l
```

For example:

```bash
dpkg -l | grep nginx
```

This lets you verify whether Nginx is installed.

---

# 10. `apt` vs `dpkg`

This is an important distinction.

### `dpkg`

Low-level Debian package management.

It works directly with `.deb` packages.

Example:

```bash
sudo dpkg -i package.deb
```

### `apt`

Higher-level package management.

It handles repositories and dependency resolution.

Example:

```bash
sudo apt install nginx
```

Think:

```text
                APT
                 ↓
     Repository + Dependencies
                 ↓
               dpkg
                 ↓
          Install .deb
                 ↓
              System
```

You normally use **APT** for everyday package installation.

---

# 11. Real example: Installing Nginx

You run:

```bash
sudo apt install nginx
```

Conceptually:

```text
You
 ↓
APT
 ↓
Find nginx
 ↓
Check dependencies
 ↓
Download .deb packages
 ↓
Verify package information
 ↓
dpkg unpacks packages
 ↓
Configuration scripts run
 ↓
Nginx installed
```

You can then check:

```bash
nginx -v
```

and:

```bash
systemctl status nginx
```

---

# 12. Why this matters for your deployment

Remember your goal:

> **Deploy your MERN application directly on Linux instead of relying on Render/Vercel.**

When you get a fresh VPS:

```text
Fresh Ubuntu VPS
       ↓
apt update
       ↓
apt install
       ↓
Git
Node.js
Nginx
etc.
       ↓
Deploy application
```

So `apt` is basically one of the tools that lets you **turn a fresh Linux machine into a usable production server**.

 **"APT vs dpkg?"**

Say:
