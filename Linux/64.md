
# Q64 — How do you uninstall software in Linux?

On Ubuntu/Debian, you generally use `apt` to uninstall packages.

Suppose you installed Nginx:

```bash
sudo apt install nginx
```

Now you want to remove it.

---

## 1. `apt remove`

The basic command is:

```bash
sudo apt remove nginx
```

This removes the **Nginx package/software**, but can leave its configuration files behind.

Think:

```text
nginx
 ↓
remove
 ↓
Program removed
Configuration may remain
```

---

## 2. `apt purge`

If you also want to remove package-managed configuration files:

```bash
sudo apt purge nginx
```

Think:

```text
remove
 ↓
Software removed
Configuration may remain


purge
 ↓
Software removed
Configuration removed
```

### Easy memory trick:

> **remove = remove the program**

> **purge = remove the program + package configuration**

---

## 3. What about dependencies?

Suppose you installed:

```text
nginx
 ↓
dependency A
 ↓
dependency B
```

Later you remove Nginx:

```bash
sudo apt remove nginx
```

Some dependencies may no longer be needed.

You can ask APT to remove automatically installed packages that are no longer required:

```bash
sudo apt autoremove
```

So a common cleanup could be:

```bash
sudo apt remove nginx
sudo apt autoremove
```

But **don't blindly run `autoremove` on a production server** without reviewing what it proposes to remove.

---

# 4. `remove` vs `purge` vs `autoremove`

| Command              | Purpose                                                  |
| -------------------- | -------------------------------------------------------- |
| `apt remove nginx` | Remove package                                           |
| `apt purge nginx`  | Remove package + package-managed configuration           |
| `apt autoremove`   | Remove automatically installed packages no longer needed |

---

# 5. Real example

Suppose you're practicing Nginx on your VPS.

Install:

```bash
sudo apt install nginx
```

Check:

```bash
nginx -v
```

Then remove:

```bash
sudo apt remove nginx
```

Check:

```bash
nginx -v
```

It should no longer be available as an installed command.

If you want to remove its package-managed configuration too:

```bash
sudo apt purge nginx
```

---

# 6. Important: `apt remove` doesn't mean "delete every Nginx file"

This is important for deployment.

Nginx can have:

```text
/etc/nginx/
/var/log/nginx/
/var/www/
```

Not every file associated with an application is necessarily removed just because you run:

```bash
sudo apt remove nginx
```

Package removal and manually created application/configuration/data files are different things.

**Never assume that uninstalling a package automatically deletes all your application data.**

---

# 7. Why this matters for your server

Imagine you've deployed:

```text
Linux VPS
│
├── Nginx
├── Node.js
├── Git
└── Your Express application
```

You don't want to randomly delete directories like:

```bash
rm -rf /etc/nginx
```

just because you're trying to uninstall Nginx.

Use the package manager:

```bash
sudo apt remove nginx
```

or:

```bash
sudo apt purge nginx
```

This lets the package-management system handle the package properly.

---

# 🧠 Interview Question

### "What's the difference between `apt remove` and `apt purge`?"

Strong answer:

> "`apt remove` uninstalls the package while generally leaving package-managed configuration files, whereas `apt purge` also removes those package-managed configuration files."

If they ask:

### "What does `apt autoremove` do?"

> "It removes packages that were automatically installed as dependencies and are no longer required."

---
