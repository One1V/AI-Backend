# Q67 — How does the `PATH` environment variable work?

`PATH` is one of the **most important Linux environment variables**.

It tells the shell **which directories to search when you type a command**.

For example, when you type:

```bash
node
```

Linux has to find the `node` executable somewhere.

`PATH` tells it where to look.

---

# 1. What is PATH?

Check your PATH:

```bash
echo $PATH
```

You might see something like:

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

Notice the `:`.

It separates different directories:

```text
/usr/local/sbin
      ↓
/usr/local/bin
      ↓
/usr/sbin
      ↓
/usr/bin
      ↓
/sbin
      ↓
/bin
```

---

# 4. What happens if a directory isn't in PATH?

Suppose you create your own executable:

```bash
/home/ayush/mytools/hello
```

Then try:

```bash
hello
```

You might get:

```text
hello: command not found
```

Why?

Because:

```text
/home/ayush/mytools
```

isn't in your `PATH`.

The shell doesn't know that it should search there.

---

# 5. Add a directory to PATH

You can temporarily add it:

```bash
export PATH="$PATH:/home/ayush/mytools"
```

Now:

```bash
hello
```

can work if `hello` is executable.

Conceptually:

```text
Before:

PATH
 ├── /usr/bin
 ├── /bin
 └── ...

After:

PATH
 ├── /usr/bin
 ├── /bin
 ├── ...
 └── /home/ayush/mytools
```

---

# 6. Why `$PATH`?

When you write:

```bash
echo $PATH
```

the `$` means:

> Give me the value stored in the `PATH` variable.

Compare:

```bash
echo $PATH
```

with:

```bash
echo PATH
```

The first prints the variable's value.

The second simply prints:

```text
PATH
```

---

# 7. Why do we write `$PATH` when modifying it?

Suppose:

```bash
export PATH="$PATH:/my/new/directory"
```

This means:

```text
New PATH
=
Existing PATH
+
/my/new/directory
```

This is important.

If you instead do:

```bash
export PATH="/my/new/directory"
```

you replace the existing PATH.

You could then lose access to commands such as:

```bash
ls
git
node
npm
```

depending on where they're installed.

So normally use:

```bash
export PATH="$PATH:/new/directory"
```

# 8. `which` and `PATH`

You can investigate commands using:

```bash
which node
```

Example:

```text
/usr/bin/node
```

You can also use:

```bash
which npm
```

Maybe:

```text
/usr/bin/npm
```

This helps you understand:

```text
Command
   ↓
PATH
   ↓
Executable location
```

---

# 9. Why PATH matters to Node.js

Suppose you install Node.js.

After installation:

```bash
node -v
```

works.

Why?

Because the Node executable is located in a directory that the shell searches through `PATH`.

This is especially important when you use tools such as **nvm**.

For example, NVM may modify your environment so that a particular Node.js version's `bin` directory appears in `PATH`.

Then:

```bash
node
```

points to that selected version.

Conceptually:

```text
NVM
 ↓
PATH changes
 ↓
Node.js version selected
 ↓
node command
```

---

# 10. PATH and your deployment

Imagine your VPS contains:

```text
/usr/bin/node
```

Your Express application runs:

```bash
node server.js
```

The shell needs to find:

```text
node
```

It uses:

```text
PATH
```

to locate it.

Later, when you configure a service with `systemd` or use PM2, **PATH and the execution environment become important**, because services may not receive exactly the same shell environment as your interactive SSH session.

This is a common source of:

```text
command not found
```

deployment problems.

# 11. Simple experiment

Run:

```bash
echo $PATH
```

Then:

```bash
which node
```

Then:

```bash
which npm
```

Then:

```bash
which git
```

You'll see where your system finds these commands.

# 🧠 Interview Answer

If asked:

> **"What is PATH in Linux?"**

Say:

> **"`PATH` is an environment variable containing a list of directories that the shell searches when locating executable commands. It allows us to run commands like `node`, `git`, and `ls` without specifying their full filesystem paths."**

If asked:

> **"What happens when I type `node`?"**

A strong answer:

```text
node
 ↓
Shell searches directories in PATH
 ↓
Finds Node executable
 ↓
Executes it
```
