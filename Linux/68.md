# Q68 — `.bashrc` vs `.profile`

Both `.bashrc` and `.profile` are **shell configuration files** commonly found in a user's home directory.

They are used to configure your shell environment, such as:

* `PATH`
* aliases
* environment variables
* shell functions
* commands that should run when a shell starts

But they are **not loaded in exactly the same situations**.

---

# 1. Where are they?

For a user named `ayush`:

```text
/home/ayush/
    │
    ├── .bashrc
    └── .profile
```

Because they start with `.` they're hidden files.

You can see them with:

```bash
ls -la
```

---

# 2. `.bashrc`

`.bashrc` is primarily used to configure **interactive Bash shells**.

For example:

```bash
alias ll='ls -lah'
```

Then when you open an interactive Bash shell, you can use:

```bash
ll
```

instead of:

```bash
ls -lah
```

You might also put shell-specific configuration here.

---

# 3. `.profile`

`.profile` is commonly used for **login-shell/session initialization**.

It can be used to set environment variables that should be available when you log in.

For example:

```bash
export PATH="$PATH:$HOME/bin"
```

Conceptually:

```text
Login/session starts
        ↓
.profile
        ↓
Environment configured
        ↓
Shell/application
```

---

# 4. Why does this matter?

Suppose you install a tool and add:

```bash
export PATH="$PATH:$HOME/mytools"
```

to `.bashrc`.

When a new interactive Bash shell starts, it may have that PATH modification.

But if something starts in a different context—for example, a service managed by `systemd`—you **cannot assume it will read your `.bashrc`**.

This is very important in deployment.

---

# 5. SSH example

Suppose you SSH into your VPS:

```bash
ssh ubuntu@SERVER_IP
```

You get a shell:

```text
ubuntu@server:~$
```

Your shell/session initialization can involve files such as:

```text
.profile
   ↓
.bashrc
   ↓
Interactive Bash environment
```

The exact startup behavior depends on whether Bash is a login shell, interactive shell, and how the distribution configures these files.

Ubuntu commonly has `.profile` arrange for `.bashrc` to be sourced for interactive Bash sessions.

---

# 6. Why are they called hidden files?

Because they begin with:

```text
.
```

For example:

```text
.bashrc
.profile
```

Normal:

```bash
ls
```

may not show them.

Use:

```bash
ls -la
```

to see them.

---

# 9. `.bashrc` vs `.profile`

The easiest way to remember:

| File         | Main purpose                             |
| ------------ | ---------------------------------------- |
| `.bashrc`  | Interactive Bash shell configuration     |
| `.profile` | Login/session environment initialization |

Don't memorize the simplistic rule:

> `.bashrc` = terminal and `.profile` = everything else.

Shell startup behavior is more nuanced.

---

---

# 11. `source` command

You'll often see:

```bash
source ~/.bashrc
```

This tells the current shell to read and execute the commands in `.bashrc`.

For example, after adding:

```bash
export MY_NAME="Ayush"
```

you can run:

```bash
source ~/.bashrc
```

Then:

```bash
echo $MY_NAME
```

will show:

```text
Ayush
```

You could also use:

```bash
. ~/.bashrc
```

The `.` is a shorthand for `source` in Bash.
