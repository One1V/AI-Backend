
# Q70 — How do you export Environment Variables in Linux?

Now we'll connect **Linux environment variables → Node.js → Express**, because this is something you'll actually use when deploying your backend.

---

# 1. Set a variable

In your terminal:

```bash
PORT=5000
```

Now try:

```bash
echo $PORT
```

You may see:

```text

```

Why?

Because simply writing:

```bash
PORT=5000
```

creates a **shell variable**, but it isn't automatically exported to child processes.

---

# 2. Use `export`

Instead:

```bash
export PORT=5000
```

Now:

```bash
echo $PORT
```

gives:

```text
5000
```

More importantly, child processes can inherit it.

---

# 3. Why does `export` matter?

Consider:

```text
Linux shell
    │
    ├── PORT=5000
    │
    └── Node.js process
```

Without `export`, the shell knows about `PORT`, but a child process doesn't automatically inherit it.

With:

```bash
export PORT=5000
```

you get:

```text
Shell
  │
  │ exported environment
  ▼
Node.js
  │
  ▼
process.env.PORT
```

That's the important concept.

---

# 4. Real Node.js example

Create:

```bash
nano server.js
```

Put:

```javascript
console.log("PORT =", process.env.PORT);
```

Now:

```bash
export PORT=5000
node server.js
```

Output:

```text
PORT = 5000
```

Node inherited the environment variable from the shell.

---

# 5. One-command version

You don't always need a separate `export`.

You can do:

```bash
PORT=5000 node server.js
```

This gives the `node` process an environment variable:

```text
PORT=5000
```

So:

```text
PORT=5000 node server.js
       ↓
Node process
       ↓
process.env.PORT
       ↓
5000
```

This is very useful for testing.

---

# 6. Multiple variables

You can export several:

```bash
export PORT=5000
export NODE_ENV=production
export JWT_SECRET="my-secret"
```

Check:

```bash
echo $PORT
echo $NODE_ENV
```

Node can access them:

```javascript
console.log(process.env.PORT);
console.log(process.env.NODE_ENV);
console.log(process.env.JWT_SECRET);
```

---

# 7. See all environment variables

Run:

```bash
env
```

or:

```bash
printenv
```

You'll see many variables:

```text
HOME=/home/ayush
USER=ayush
PATH=/usr/local/bin:...
SHELL=/bin/bash
...
```

You can search:

```bash
printenv | grep PORT
```

---

# 8. `export` vs normal variable

This is an important interview concept.

### Normal shell variable

```bash
PORT=5000
```

Available in the current shell:

```text
Shell
 └── PORT=5000
```

But not automatically inherited by child processes.

### Exported variable

```bash
export PORT=5000
```

Now:

```text
Shell
   │
   └── exported PORT
          ↓
      Child process
```

---

# 9. Real deployment example

Imagine your Express server:

```javascript
const PORT = process.env.PORT || 5000;

app.listen(PORT);
```

On your VPS:

```bash
export PORT=5000
node server.js
```

Then:

```text
Linux
 ↓
PORT=5000
 ↓
Node process
 ↓
process.env.PORT
 ↓
Express
 ↓
Port 5000
```

This is exactly how your Linux environment can provide configuration to your backend.

---

# 10. What happens when you close SSH?

This is important because you've already studied Linux processes.

Suppose you run:

```bash
export PORT=5000
node server.js
```

Your Node process inherits:

```text
PORT=5000
```

But the environment belongs to that process/session.

When you log out, the process may be terminated depending on how it was started and how the session is managed.

That's why production applications use things like:

```text
systemd
PM2
Docker
```

instead of relying on a manually opened SSH shell.

We'll cover this later.

---

# 11. Make the variable persistent

If you want an environment variable to be available in future Bash sessions, you can put the export command in an appropriate shell startup file.

For example:

```bash
nano ~/.bashrc
```

Add:

```bash
export MY_VARIABLE="hello"
```

Then:

```bash
source ~/.bashrc
```

Now:

```bash
echo $MY_VARIABLE
```

returns:

```text
hello
```

But remember from **Q68**:

> Shell startup files are not universal configuration for every process.

A `systemd` service doesn't simply become configured because you put something in `.bashrc`.

---

# 12. Production lesson

For your eventual deployment:

```text
Browser
   ↓
Nginx
   ↓
Express
   ↓
process.env.MONGO_URI
```

The value might come from:

```text
systemd environment
       OR
.env loaded by application
       OR
another deployment/configuration mechanism
```

The application only sees:

```javascript
process.env.MONGO_URI
```

This separation is extremely useful.

---

# 🧠 Interview Answer

If asked:

> **"How do you set an environment variable in Linux?"**

Say:

```bash
export PORT=5000
```

Then explain:

> "`export` marks the shell variable for inheritance by child processes, so applications launched from that shell can access it through their environment."

If asked:

> **"What's the difference between `PORT=5000` and `export PORT=5000`?"**

Say:

> "`PORT=5000` creates or sets a shell variable, while `export PORT=5000` also makes it available to child processes."
