# Q72 — Mini Project: Configure Environment Variables for Express

This is the **final question of Module 8 — Environment & Configuration**.

The goal is to take the Express application you've already built and make its configuration **environment-based instead of hard-coded**.

---

# 🎯 Goal

We'll build this:

```text
Linux / Environment
       │
       ├── PORT
       ├── NODE_ENV
       └── MONGO_URI
       │
       ▼
    Node.js
       │
       ▼
    Express
```

And locally:

```text
.env
 ↓
dotenv
 ↓
process.env
 ↓
Express
```

---

# Step 1 — Create the project

Create a simple Express project:

```bash
mkdir env-demo
cd env-demo
npm init -y
npm install express dotenv
```

Create:

```text
env-demo/
├── server.js
├── .env
├── .gitignore
└── package.json
```

---

# Step 2 — Create `.env`

Create:

```bash
nano .env
```

Put:

```env
PORT=5000
NODE_ENV=development
```

You could later add:

```env
MONGO_URI=your_database_url
JWT_SECRET=your_secret
```

but don't use real secrets for this practice project.

---

# Step 3 — Load `.env`

In `server.js`:

```javascript
require("dotenv").config();

const express = require("express");

const app = express();

const PORT = process.env.PORT || 3000;

app.get("/", (req, res) => {
    res.json({
        message: "Server is working",
        environment: process.env.NODE_ENV
    });
});

app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);
});
```

---

# Step 4 — Start the server

Run:

```bash
node server.js
```

You should see:

```text
Server running on port 5000
```

Why 5000?

Because:

```text
.env
 ↓
PORT=5000
 ↓
dotenv
 ↓
process.env.PORT
 ↓
Express
 ↓
Port 5000
```

---

# Step 5 — Test it

Open:

```text
http://localhost:5000
```

You should receive something like:

```json
{
  "message": "Server is working",
  "environment": "development"
}
```

Notice that the browser gets:

```text
development
```

but it does **not** automatically get the entire `.env` file.

Your application explicitly chose what to return:

```javascript
environment: process.env.NODE_ENV
```

---

# Step 6 — Test without `.env`

Stop the server:

```bash
Ctrl + C
```

Temporarily rename:

```bash
mv .env .env.backup
```

Then run:

```bash
node server.js
```

Now:

```javascript
const PORT = process.env.PORT || 3000;
```

has no `PORT` from `.env`.

Therefore:

```text
process.env.PORT
        ↓
undefined
        ↓
3000
```

So your server should run on:

```text
localhost:3000
```

This demonstrates why we use:

```javascript
process.env.PORT || 3000
```

---

# Step 7 — Restore `.env`

Run:

```bash
mv .env.backup .env
```

Now:

```bash
node server.js
```

will again use:

```text
5000
```

---

# Step 8 — Test Linux environment variables

Now let's deliberately **not use `.env`**.

Stop the server and run:

```bash
PORT=7000 NODE_ENV=production node server.js
```

Now the server should start on:

```text
7000
```

And if you visit:

```text
http://localhost:7000
```

you should get:

```json
{
  "message": "Server is working",
  "environment": "production"
}
```

This is extremely important because you just demonstrated two different ways of providing configuration.

### `.env`

```text
.env
 ↓
dotenv
 ↓
process.env
 ↓
Node
```

### Linux environment

```text
Linux
 ↓
PORT=7000
 ↓
Node
 ↓
process.env
```

---

# Step 9 — Protect `.env`

Create `.gitignore`:

```bash
nano .gitignore
```

Add:

```text
.env
```

Now:

```bash
git status
```

Your `.env` should not appear as an untracked file.

---

# Step 10 — Create `.env.example`

Create:

```bash
touch .env.example
```

Put:

```env
PORT=5000
NODE_ENV=development
MONGO_URI=
JWT_SECRET=
```

This file **can** be committed.

It tells other developers which variables they need.

---

You should have:

│

# 🧠 What this project teaches you

You've now connected **four things**:

### 1. Linux

```bash
export PORT=5000
```

### 2. `.env`

```env
PORT=5000
```

### 3. Node.js

```javascript
process.env.PORT
```

### 4. Express

```javascript
app.listen(process.env.PORT)
```

Complete flow:

```text
             Configuration
                  │
          ┌───────┴────────┐
          ↓                ↓
        .env          Linux environment
          │                │
          ↓                ↓
       dotenv          process
          │                │
          └───────┬────────┘
                  ↓
             process.env
                  ↓
               Node.js
                  ↓
               Express
```

# 🎯 Interview Questions From This Project

### Q: How does Node access environment variables?

```javascript
process.env.PORT
```

### Q: How do you load a `.env` file?

```javascript
require("dotenv").config();
```

### Q: Should `.env` be committed?

Usually **no**, if it contains secrets.

### Q: What should you commit instead?

```text
.env.example
```

### Q: Is `.env` the same as an environment variable?

No.

```text
.env = configuration file

environment variable = value available to a process
```
