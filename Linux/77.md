
# Q77 — How do you identify high CPU usage in Linux?

This is a very practical production question.

Imagine your deployed backend is:

```text
Browser
   ↓
Nginx
   ↓
Express
   ↓
MongoDB
```

Suddenly users complain:

> "The website is very slow."

One possibility is **high CPU usage** on your Linux server.

---

# 1. First tool: `top`

Run:

```bash
top
```

You'll see something similar to:

```text
top - 10:30:20 up 5 days,  2 users
Tasks: 150 total
%Cpu(s): 85.0 us, 10.0 sy,  5.0 id
```

The important part is:

```text
%Cpu(s): 85.0 us, 10.0 sy, 5.0 id
```

Here:

* `us` → CPU used by user processes
* `sy` → CPU used by the kernel/system
* `id` → idle CPU

So:

```text
5% idle
```

means the CPU is heavily utilized.

---

# 2. Find which process is consuming CPU

Inside `top`, you'll see processes like:

```text
PID    USER     %CPU    %MEM    COMMAND
1234   ubuntu   95.0    4.2     node
2311   root     20.0    1.1     nginx
1542   mongodb  15.0    8.5     mongod
```

Here:

```text
node → 95% CPU
```

is suspicious.

Your Node.js application might be consuming most of the CPU.

---

# 3. `htop`

You've already learned what `htop` is.

Run:

```bash
htop
```

It provides a more interactive view.

You'll see something like:

```text
CPU  [|||||||||||||||||     ] 85%
MEM  [||||||||              ] 40%

PID    USER    CPU%    MEM%    COMMAND
1234   ubuntu  95.0    4.2     node
2311   root    20.0    1.1     nginx
```

It's often easier to inspect than `top`.

---

# 4. `ps`

You can also use:

```bash
ps aux
```

This lists processes.

To sort by CPU usage:

```bash
ps aux --sort=-%cpu
```

Now the highest CPU-consuming processes appear near the top.

Example:

```text
USER     PID   %CPU   %MEM   COMMAND
ubuntu   1234  95.0   4.2    node server.js
root     2311  20.0   1.1    nginx
mongodb  1542  15.0   8.5    mongod
```

This is very useful when debugging from the command line.

---

# 5. Find the Node process

You can specifically search:

```bash
ps aux | grep node
```

You might see:

```text
ubuntu  1234  95.0  4.2  node server.js
```

Now you know:

```text
PID = 1234
CPU = 95%
```

---

# 6. Why could Node use high CPU?

This is where backend knowledge matters.

Suppose you accidentally write:

```javascript
while (true) {
    console.log("hello");
}
```

That loop never ends.

Your Node process could consume enormous CPU.

Conceptually:

```text
Node.js
   ↓
Infinite loop
   ↓
CPU continuously busy
   ↓
High CPU usage
```

---

# 7. Another example: expensive computation

Suppose an API does:

```javascript
app.get("/calculate", (req, res) => {
    // Extremely expensive computation
});
```

If thousands of users call it simultaneously:

```text
1000 requests
      ↓
Heavy computation
      ↓
Node CPU usage ↑
      ↓
Server becomes slow
```

Linux tools can show you **that** the Node process is consuming CPU, although you'll need application-level profiling/monitoring to determine exactly which code path is responsible.

---

# 8. Check CPU load

You can also run:

```bash
uptime
```

Example:

```text
load average: 3.20, 2.80, 2.50
```

The three numbers represent load averages over approximately:

```text
1 minute
5 minutes
15 minutes
```

But don't interpret the load average as a simple "CPU percentage."

Its meaning depends on the number of CPU cores and what processes are waiting for.

For example, on a 4-core machine:

```text
load average: 1.0
```

is very different from:

```text
load average: 8.0
```

---

# 9. CPU percentage vs load average

This is a common interview trap.

### CPU utilization

```text
How busy are the CPUs?
```

Tools:

```bash
top
htop
```

### Load average

```text
How much runnable/uninterruptible work is accumulating?
```

Tools:

```bash
uptime
top
```

Don't say:

> "Load average is CPU percentage."

It isn't.

---

# 10. Real production debugging

Suppose users report:

> "The API has become extremely slow."

You SSH into your VPS:

```bash
ssh ubuntu@SERVER_IP
```

First:

```bash
top
```

You discover:

```text
node    98% CPU
```

Then:

```bash
ps aux --sort=-%cpu | head
```

confirms:

```text
node server.js → 98%
```

Then you investigate your application.

You might check:

```bash
sudo journalctl -u myapp -f
```

and application metrics/profiling if necessary.

So:

```text
Users report slowness
        ↓
Check CPU
        ↓
top / htop
        ↓
Find process
        ↓
ps
        ↓
Node consuming CPU?
        ↓
Investigate application
```

---

# 11. What NOT to do immediately

Suppose you see:

```text
node → 100% CPU
```

Don't immediately do:

```bash
kill -9 PID
```

You learned earlier that `SIGKILL` is forceful.

First investigate:

```text
Why is it using CPU?
```

Otherwise you might simply kill your production backend and make the outage worse.

---

# 🧠 Interview Answer

If asked:

> **"How would you identify high CPU usage on a Linux server?"**

A strong answer:

> **"I'd first use `top` or `htop` to check overall CPU utilization and identify processes consuming CPU. I can also use `ps aux --sort=-%cpu` to list processes by CPU usage. If Node.js is consuming excessive CPU, I'd then inspect its logs and application behavior to determine the cause."**

Useful commands:

```bash
top
```

```bash
htop
```

```bash
ps aux --sort=-%cpu
```

```bash
uptime
```
