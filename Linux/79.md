
# Q79 — How do you identify disk usage with `df` and `du`?

This is another very common **Linux production troubleshooting** question.

Suppose your VPS suddenly says:

```text
No space left on device
```

Your Node.js application may stop writing files, Nginx may fail to write logs, databases may have problems, or deployments may fail.

You need to find **where the disk space went**.

---

# 1. First: `df`

`df` tells you about **filesystem-level disk usage**.

Run:

```bash
df -h
```

Example:

```text
Filesystem      Size  Used  Avail  Use%
/dev/sda1       40G   35G   5G     88%
```

The `-h` means:

> Human-readable.

---

# 2. Understanding `df -h`

Suppose:

```text
Filesystem      Size   Used   Avail   Use%
/dev/sda1       40G    35G     5G     88%
```

Meaning:

```text
Total disk     → 40 GB
Used           → 35 GB
Available      → 5 GB
Usage          → 88%
```

So:

```text
40 GB
███████████████████████████████░░░░░░░
             88% used
```

If this approaches 100%, you have a serious disk-space problem.

---

# 3. Why can a backend server run out of disk?

Your VPS might contain:

```text
Application code
Nginx logs
Application logs
Docker images
Docker containers
Uploaded files
Database files
Temporary files
Backups
```

For example:

```text
VPS
│
├── Node application
├── Nginx
├── MongoDB
├── Docker
├── Logs
└── Backups
```

Over time, logs or uploaded files can consume a lot of space.

---

# 4. `du`

Now you know:

> "My disk is 90% full."

But **what is consuming the space?**

That's where `du` comes in.

`du` means:

> **disk usage**

For example:

```bash
du -sh /var/log
```

You might get:

```text
8.5G    /var/log
```

Now you know `/var/log` is using 8.5 GB.

---

# 5. `df` vs `du`

This is the most important thing to remember:

### `df`

```bash
df -h
```

Answers:

> **How much space is used on the filesystem?**

### `du`

```bash
du -sh /path
```

Answers:

> **How much disk space is being used by this directory/path?**

Think:

```text
df → filesystem level
du → directory/file level
```

---

# 6. Find which directories are large

Suppose:

```bash
sudo du -sh /var/*
```

You might see:

```text
2.0G    /var/cache
8.5G    /var/log
12G     /var/lib
500M    /var/tmp
```

Now you know:

```text
/var/lib
```

is particularly large.

You can investigate further:

```bash
sudo du -sh /var/lib/*
```

Maybe:

```text
10G    /var/lib/docker
1.5G   /var/lib/mongodb
```

Now you've narrowed it down.

---

# 7. Find large files

You can use:

```bash
sudo du -ah /var | sort -h | tail
```

This can show the largest files/directories under `/var`.

For example:

```text
5.0G /var/log/myapp.log
8.0G /var/lib/docker
```

Now you have something concrete to investigate.

---

# 8. Real example: logs filling your VPS

Suppose your Node application produces:

```text
GET /api/users
POST /api/login
...
```

and you've been running it for six months.

Your log file grows:

```text
myapp.log
     ↓
100 MB
     ↓
500 MB
     ↓
2 GB
     ↓
10 GB
```

Eventually:

```text
df -h
```

shows:

```text
Use% = 99%
```

You investigate:

```bash
sudo du -sh /var/log/*
```

and discover:

```text
10G /var/log/myapp.log
```

Now you've found the cause.

In a real production environment, you'd normally configure **log rotation/retention** rather than simply deleting logs blindly.

---

# 9. Nginx example

Your Nginx logs may be:

```text
/var/log/nginx/access.log
/var/log/nginx/error.log
```

Check their size:

```bash
sudo du -sh /var/log/nginx/*
```

You might discover:

```text
4.2G /var/log/nginx/access.log
500M /var/log/nginx/error.log
```

That's a warning that log management needs attention.

---

# 10. Docker example

Later in your roadmap, you'll learn Docker.

Docker can consume significant disk space through:

```text
Images
Containers
Volumes
Build cache
Logs
```

You might find:

```text
/var/lib/docker
```

is huge.

Don't manually delete random files inside Docker's storage directory.

Instead, use Docker's own commands to inspect and manage its resources.

For example:

```bash
docker system df
```

This tells you how much disk space Docker is using.

---

# 11. A very common production scenario

Imagine:

```text
VPS
40 GB disk
```

Your application has:

```text
Node.js        2 GB
Nginx          500 MB
MongoDB        8 GB
Docker         12 GB
Logs           15 GB
```

Total:

```text
37.5 GB
```

Then:

```bash
df -h
```

might show:

```text
40G total
38G used
2G available
```

You then investigate with:

```bash
sudo du -sh /*
```

and drill down into the largest directories.

---

# 12. Important: `df` and `du` can sometimes disagree

You might see:

```text
df -h
```

says:

```text
90% used
```

but:

```text
du -sh /
```

doesn't seem to account for all that space.

One possible reason is **deleted files that are still held open by a running process**.

Conceptually:

```text
Process
   ↓
opens large.log
   ↓
large.log is deleted
   ↓
filename disappears
   ↓
process still has file open
   ↓
disk blocks remain allocated
```

You can investigate open deleted files with tools such as:

```bash
sudo lsof +L1
```

This is a more advanced troubleshooting case, but it's good to know it exists.

---

# 13. Real debugging workflow

Suppose deployment suddenly fails:

```text
No space left on device
```

Don't randomly delete files.

Use:

### Step 1

```bash
df -h
```

Check filesystem usage.

### Step 2

Find large directories:

```bash
sudo du -sh /var/*
```

### Step 3

Drill deeper:

```bash
sudo du -sh /var/log/*
```

### Step 4

Find the cause.

Possibilities:

```text
Logs
Docker
Backups
Uploads
Database
Cache
```

### Step 5

Clean/manage the responsible resource appropriately.

---

# 🧠 Interview Answer

If asked:

> **"What's the difference between `df` and `du`?"**

Give this:

> **"`df` shows disk-space usage at the filesystem level, while `du` shows how much disk space particular files and directories are consuming."**

Example:

```bash
df -h
```

→ overall filesystem usage.

```bash
du -sh /var/log
```

→ usage of `/var/log`.

If asked:

> **"How would you debug a server with no disk space?"**

Say:

```text
df -h
   ↓
Identify full filesystem
   ↓
du -sh directories
   ↓
Find large files/directories
   ↓
Investigate logs, Docker, uploads, backups, etc.
   ↓
Clean/manage the responsible resource
```

```text
             ↓

             ↓

```

```bash
df -h
```

**Overall disk usage**

```bash
du -sh /path
```

**Directory usage**

```bash
sudo du -sh /var/*
```
