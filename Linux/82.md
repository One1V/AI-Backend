
# Q82 — What is a service in Linux?

A **service** is a program that runs in the background and performs some function, usually continuously or whenever needed.

In backend development, you can think of a service as a **long-running process that Linux manages for you**.

---

## 1. Real examples

Your Linux server may have:

```text
Linux Server
│
├── SSH service
├── Nginx service
├── MongoDB service
├── Docker service
└── Your Node.js service
```

For example:

```text
nginx.service
```

runs the Nginx web server.

Your backend could be:

```text
myapp.service
```

running:

```text
Node.js → Express
```

---

# 2. Why do we need services?

Imagine you deploy your Express backend.

Without a service:

```text
SSH
 ↓
node server.js
 ↓
Express running
```

You have to manually start it.

If the server reboots:

```text
VPS reboots
    ↓
Linux starts
    ↓
Node application ❌
```

Your website goes down.

With a service:

```text
VPS reboots
    ↓
Linux boots
    ↓
systemd
    ↓
myapp.service
    ↓
Node.js
    ↓
Express
```

Your application can start automatically.

---

# 3. Service = managed background application

Suppose you create:

```text
myapp.service
```

Linux now knows:

> "This is an application that I need to manage."

You can control it using:

```bash
sudo systemctl start myapp
```

```bash
sudo systemctl stop myapp
```

```bash
sudo systemctl restart myapp
```

```bash
sudo systemctl status myapp
```

---

# 4. Example: Nginx

Check Nginx:

```bash
sudo systemctl status nginx
```

You might see:

```text
● nginx.service
     Active: active (running)
```

That means:

```text
systemd
   ↓
nginx.service
   ↓
Nginx process
   ↓
Port 80/443
```

---

# 5. Your Express application as a service

Suppose your project is:

```text
/home/ayush/myapp/
├── server.js
├── package.json
└── .env
```

Normally:

```bash
node server.js
```

Instead, you can create:

```text
/etc/systemd/system/myapp.service
```

Then:

```bash
sudo systemctl start myapp
```

Now:

```text
systemd
   ↓
myapp.service
   ↓
node server.js
   ↓
Express
```

---

# 6. Service vs process

These are related but **not exactly the same thing**.

### Process

A running instance of a program.

Example:

```text
node server.js
```

is running as a process with a PID:

```text
PID = 1234
```

### Service

A **managed application/process**, usually configured to run in the background and be controlled by a service manager such as systemd.

So:

```text
Program
   ↓
Process
   ↓
Managed by systemd
   ↓
Service
```

More precisely, a systemd service is represented by a **unit configuration** describing how the service should be managed.

---

# 7. Service can restart after failure

Suppose:

```text
myapp.service
      ↓
Node.js
      ↓
CRASH ❌
```

If configured with:

```ini
Restart=always
```

systemd can restart it:

```text
Node crashes
     ↓
systemd detects failure
     ↓
Node restarts
     ↓
Express available again
```

This is one of the biggest benefits of running your backend as a service.

---

# 8. Service can start after boot

You can enable it:

```bash
sudo systemctl enable myapp
```

Then:

```text
Server reboot
     ↓
Linux boots
     ↓
systemd
     ↓
myapp.service
     ↓
Express starts
```

So you don't need to SSH into the server every time it restarts.

---

# 9. Common services you'll encounter

As a backend developer:

| Service    | Purpose                   |
| ---------- | ------------------------- |
| `ssh`    | Remote server access      |
| `nginx`  | Web server/reverse proxy  |
| `mongod` | MongoDB database          |
| `docker` | Container management      |
| `myapp`  | Your Node/Express backend |

You can check:

```bash
systemctl status nginx
```

or:

```bash
systemctl status ssh
```

---

# 10. Service status is extremely useful for debugging

Suppose your website gives:

```text
502 Bad Gateway
```

You can check:

```bash
sudo systemctl status myapp
```

If you see:

```text
Active: failed
```

you immediately know:

```text
Nginx
   ↓
Express
   ↓
❌ Express service is down
```

Then inspect:

```bash
sudo journalctl -u myapp
```

This connects directly to the logging concepts from Q73–80.

---

# 🧠 Interview Answer

If asked:

> **"What is a service in Linux?"**

Say:

> **"A service is a background program or long-running application managed by the operating system's service manager. On Linux, systemd commonly manages services such as Nginx, SSH, Docker, and custom Node.js applications. Services can be started, stopped, restarted, monitored, and configured to start automatically at boot."**

If they ask:

> **"Why would you run Express as a service?"**

Say:

> **"It allows Linux to manage the application, restart it after failures, start it automatically after reboot, and provide centralized status and logs."**
