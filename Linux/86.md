
# Q86 — PM2 vs `systemd`

Both **PM2** and **systemd** can be used to keep your Node.js/Express application running in production.

The important thing is understanding **what each one is designed for**.

---

# 1. PM2

PM2 is a **Node.js process manager**.

You can install it with:

```bash
npm install -g pm2
```

Then instead of:

```bash
node server.js
```

you can use:

```bash
pm2 start server.js
```

PM2 manages your Node.js process.

Conceptually:

```text
PM2
 ↓
Node.js
 ↓
Express
```

---

# 2. systemd

`systemd` is the **Linux system and service manager**.

You can configure:

```text
systemd
   ↓
myapp.service
   ↓
Node.js
   ↓
Express
```

It isn't specific to Node.js.

It can manage:

```text
Nginx
SSH
Docker
MongoDB
Node.js
Custom applications
```

---

# 3. Biggest difference

Remember this:

```text
PM2
 ↓
Node.js-focused process manager
```

while:

```text
systemd
 ↓
Linux-wide service manager
```

That's the most important distinction.

---

# 4. Starting your Express app

### With PM2

```bash
pm2 start server.js
```

Check:

```bash
pm2 status
```

Logs:

```bash
pm2 logs
```

Restart:

```bash
pm2 restart server
```

---

### With systemd

```bash
sudo systemctl start myapp
```

Check:

```bash
sudo systemctl status myapp
```

Logs:

```bash
sudo journalctl -u myapp
```

Restart:

```bash
sudo systemctl restart myapp
```

---

# 5. Automatic restart

Both can restart your application after failures.

### PM2

```bash
pm2 start server.js
```

PM2 monitors the Node process and can restart it if it crashes.

### systemd

Your service can contain:

```ini
Restart=on-failure
```

Then:

```text
Node crashes
    ↓
systemd detects failure
    ↓
Node restarts
```

So both can provide process supervision.

---

# 6. Server reboot

Both can be configured to bring your application back after a reboot.

### PM2

PM2 provides startup configuration that integrates with the system's boot process.

For example:

```bash
pm2 startup
pm2 save
```

### systemd

You can use:

```bash
sudo systemctl enable myapp
```

So:

```text
VPS reboot
     ↓
Linux boots
     ↓
Process manager
     ↓
Node starts
```

---

# 7. PM2 has Node-specific features

PM2 provides features particularly useful for Node.js applications.

For example:

### Process monitoring

```bash
pm2 monit
```

### Logs

```bash
pm2 logs
```

### Process list

```bash
pm2 list
```

### Restart

```bash
pm2 restart app
```

It also supports **cluster mode**, which can be useful for running multiple Node.js worker processes.

Conceptually:

```text
              PM2
               │
       ┌───────┼───────┐
       ↓       ↓       ↓
    Node 1   Node 2   Node 3
       │       │       │
       └───────┼───────┘
               ↓
            Express
```

This is one reason PM2 is popular in Node.js deployments.

---

# 8. systemd is more deeply integrated with Linux

systemd can manage the entire server's services.

For example:

```text
                 systemd
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
     nginx        docker       myapp
                                  ↓
                                Node
```

You can control all of them using:

```bash
systemctl start
systemctl stop
systemctl restart
systemctl status
```

This makes systemd a natural choice when you want Linux itself to manage your application's lifecycle.

---

# 9. Which one should YOU learn?

For your **Linux + backend placement preparation**, you should absolutely understand **systemd**.

Why?

Because your syllabus already covers:

```text
Linux
 ↓
Processes
 ↓
Services
 ↓
systemd
 ↓
Deployment
```

And interviewers may ask:

> "How would you run your Node application as a Linux service?"

You should be able to explain:

```text
/etc/systemd/system/myapp.service
        ↓
systemctl daemon-reload
        ↓
systemctl enable --now myapp
        ↓
Node.js
```

---

# 10. For actual Node.js projects

PM2 is also worth knowing.

A common Node deployment might look like:

```text
                    Internet
                       ↓
                     Nginx
                       ↓
                      PM2
                 ┌─────┴─────┐
                 ↓           ↓
              Node 1      Node 2
                 ↓           ↓
                 └─────┬─────┘
                       ↓
                    MongoDB
```

Whereas a systemd-based deployment might be:

```text
                    Internet
                       ↓
                     Nginx
                       ↓
                    systemd
                       ↓
                  Node / Express
                       ↓
                    MongoDB
```

---

# 11. Don't say "PM2 is better"

This is a common interview mistake.

There isn't a universal:

> **PM2 = better**

or:

> **systemd = better**

It depends on the deployment requirements.

A good answer is:

> **"PM2 is specialized for Node.js process management and provides Node-specific features such as process monitoring and cluster mode. systemd is Linux's native service manager and integrates deeply with the operating system and other services."**

That's much better.

---

# 12. PM2 vs systemd — Quick Table

|                            | PM2                         | systemd                |
| -------------------------- | --------------------------- | ---------------------- |
| Designed for               | Node.js                     | Linux services         |
| Node-specific              | ✅                          | ❌                     |
| Restart on crash           | ✅                          | ✅                     |
| Boot startup               | ✅                          | ✅                     |
| Process monitoring         | Strong Node-focused tooling | System/service focused |
| Cluster mode               | ✅                          | Not Node-specific      |
| Manages Nginx/SSH/etc.     | ❌                          | ✅                     |
| Linux-native               | ❌                          | ✅                     |
| Useful for Node deployment | ✅                          | ✅                     |

---

# 🧠 Interview Answer

If asked:

> **"What's the difference between PM2 and systemd?"**

Say:

> **"PM2 is a process manager specifically designed for Node.js applications, while systemd is Linux's native system and service manager. PM2 provides Node-specific features such as process monitoring and cluster mode, whereas systemd integrates with the whole Linux system and can manage services such as Nginx, Docker, SSH, and Node applications."**

Then add:

> **"For Linux administration and deployment, I should understand systemd; for Node-specific process management, PM2 is also useful."**
