
# Q87 — Mini Project: Deploy Express using `systemd`

This is the **final project of the Services module**. You'll take a normal Express application and make Linux manage it like a real production service.

---

# 🎯 Goal

We'll build:

```text
Internet
    ↓
Nginx
    ↓
systemd
    ↓
Node.js / Express
    ↓
MongoDB
```

For this exercise, you can do everything on your Ubuntu VPS or local Ubuntu machine.

# 1. Create the Express application

Suppose your application is:

```text
/home/ayush/myapp
```

Go there:

```bash
cd ~/myapp
```

Your structure:

```text
myapp/
├── server.js
├── package.json
├── package-lock.json
└── .env
```

Example `server.js`:

```javascript
const express = require("express");

const app = express();

app.get("/", (req, res) => {
    res.send("Express is running through systemd!");
});

app.get("/api/health", (req, res) => {
    res.json({
        status: "OK"
    });
});

app.listen(5000, () => {
    console.log("Server running on port 5000");
});
```

Test it manually first:

```bash
node server.js
```

Then from another terminal:

```bash
curl http://localhost:5000
```

You should get:

```text
Express is running through systemd!
```

Stop the manually running server with:

```text
Ctrl + C
```

---

# 2. Find the Node.js path

Run:

```bash
which node
```

You might get:

```text
/usr/bin/node
```

**Use the path returned by your own machine** in the service file.

This matters because Node installed through different methods can live in different locations.

---

# 3. Create the systemd service

Run:

```bash
sudo nano /etc/systemd/system/myapp.service
```

Put:

```ini
[Unit]
Description=My Express Backend
After=network.target

[Service]
User=ayush
WorkingDirectory=/home/ayush/myapp
ExecStart=/usr/bin/node server.js
Restart=on-failure
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

Replace:

```text
ayush
```

and:

```text
/home/ayush/myapp
```

with your actual Linux username and application path.

---

# 4. Understand the service file

The important parts are:

```ini
User=ayush
```

Node runs as this Linux user.

```ini
WorkingDirectory=/home/ayush/myapp
```

This is your application's directory.

```ini
ExecStart=/usr/bin/node server.js
```

This is the command systemd uses to start Node.

```ini
Restart=on-failure
```

If the application crashes, systemd can restart it.

```ini
WantedBy=multi-user.target
```

Allows the service to be enabled for normal multi-user boot.

---

# 5. Reload systemd

After creating the service:

```bash
sudo systemctl daemon-reload
```

Think:

```text
You changed service configuration
        ↓
daemon-reload
        ↓
systemd reads the new configuration
```

# 8. Enable automatic startup

Now run:

```bash
sudo systemctl enable myapp
```

Or simply:

```bash
sudo systemctl enable --now myapp
```

Now you have:

```text
             myapp.service
                   │
             ┌─────┴─────┐
             ↓           ↓
         Running      Boot enabled
           NOW        Future boots
```

---

# 9. Test automatic restart

This is an important part of the project.

Find the Node process:

```bash
ps aux | grep node
```

You can also inspect:

```bash
sudo systemctl status myapp
```

Suppose the PID is:

```text
1234
```

You could terminate the process:

```bash
kill 1234
```

Because you configured:

```ini
Restart=on-failure
```

systemd should detect the failure and attempt to restart it.

Check:

```bash
sudo systemctl status myapp
```

You should see the service running again.

**Don't use `kill -9` unless necessary**; normal termination is enough for this experiment.

---

# 10. Check the logs

Your Express application contains:

```javascript
console.log("Server running on port 5000");
```

systemd captures service output in the journal.

Run:

```bash
sudo journalctl -u myapp
```

For live logs:

```bash
sudo journalctl -u myapp -f
```

Now make a request:

```bash
curl http://localhost:5000
```

You can watch the application's output in the journal.

---

# 11. Test reboot behavior

This is the final test.

First confirm:

```bash
systemctl is-enabled myapp
```

Expected:

```text
enabled
```

Then reboot:

```bash
sudo reboot
```

After the server comes back, SSH into it again:

```bash
ssh ayush@SERVER_IP
```

Check:

```bash
sudo systemctl status myapp
```

You should see:

```text
Active: active (running)
```

And:

```bash
curl http://localhost:5000
```

should still work.

🎉 Your Express application is now automatically starting after Linux boots.

# 12. Now add Nginx

This connects directly to the Nginx project you've already done.

Architecture:

```text
                    Browser
                       │
                       ▼
                    Nginx
                   Port 80
                       │
                       ▼
               localhost:5000
                       │
                       ▼
                Express / Node
                       │
                  managed by
                       │
                    systemd
```

Nginx configuration could contain:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:5000;
}
```

Then:

```text
Browser
   ↓
Nginx :80
   ↓
Express :5000
```

The user doesn't need direct access to port 5000.

# 14. Your debugging commands

If the application doesn't work:

### Is the service running?

```bash
sudo systemctl status myapp
```

### Why did it fail?

```bash
sudo journalctl -u myapp -n 100
```

### Is Node listening?

```bash
sudo ss -ltnp | grep :5000
```

### Can Express respond directly?

```bash
curl http://127.0.0.1:5000
```

### Is Nginx working?

```bash
sudo systemctl status nginx
```

### Nginx errors?

```bash
sudo tail -f /var/log/nginx/error.log
```

This is now a **real production troubleshooting workflow**.
