
# Q88 — How do you deploy a MERN application on Ubuntu?

This is where **Linux + Node.js + Express + MongoDB + Nginx + Git** come together.

For a placement interview, you don't need to memorize every command. You need to understand the **deployment flow**.

---

# 1. What does "deploy" mean?

Deployment means taking your application from your development machine:

```text
Your Laptop
    ↓
Application
```

and making it available on a remote server:

```text
Internet
    ↓
Ubuntu Server / VPS
    ↓
Your Application
```

For a MERN application:

```text
React
   ↓
Nginx
   ↓
Express / Node.js
   ↓
MongoDB
```

---

# 2. Typical production architecture

A simple MERN deployment can look like:

```text
                       INTERNET
                           │
                           ▼
                        DNS
                           │
                           ▼
                    Ubuntu VPS
                           │
                           ▼
                        Nginx
                     :80 / :443
                       /       \
                      /         \
                     ▼           ▼
               React files    /api/*
                                  │
                                  ▼
                            Node / Express
                               :5000
                                  │
                                  ▼
                               MongoDB
```

Your Node application can be managed by:

```text
systemd / PM2
```

---

# 3. Step 1 — Get an Ubuntu server

You need a server with:

```text
Ubuntu
Public IP
SSH access
```

For example:

```bash
ssh ubuntu@SERVER_IP
```

Now you're working on the remote Linux machine.

---

# 4. Step 2 — Update Ubuntu

Usually:

```bash
sudo apt update
sudo apt upgrade
```

Why?

Because you want the server's package information and installed packages up to date.

---

# 5. Step 3 — Install required software

For a basic deployment you may need:

```text
Git
Node.js
Nginx
MongoDB
```

Depending on your architecture, MongoDB could instead be hosted externally, such as through a managed database provider.

You don't necessarily need MongoDB installed directly on the same VPS.

---

# 6. Step 4 — Get your code

Suppose your code is on GitHub.

On the server:

```bash
git clone YOUR_REPOSITORY
```

Then:

```bash
cd your-project
```

Now:

```text
GitHub
   ↓
git clone
   ↓
Ubuntu Server
   ↓
Your MERN code
```

This leads directly to **Q89: How Git fits into deployment.**

---

# 7. Step 5 — Install backend dependencies

Go into your backend:

```bash
cd backend
```

Then:

```bash
npm install
```

This installs dependencies from:

```text
package.json
```

and:

```text
package-lock.json
```

---

# 8. Step 6 — Configure environment variables

Your production server needs its own environment variables.

For example:

```env
PORT=5000
MONGO_URI=...
JWT_SECRET=...
NODE_ENV=production
```

You should **not** normally commit production secrets to GitHub.

Your repository should contain something like:

```text
.env.example
```

but not your real:

```text
.env
```

So:

```text
GitHub
   ↓
Code
   ↓
Server
   ↓
Production .env
```

This connects directly to the Linux permissions questions you studied.

---

# 9. Step 7 — Start the backend

You could test it manually:

```bash
npm start
```

or:

```bash
node server.js
```

If your Express server listens on:

```text
localhost:5000
```

test it:

```bash
curl http://localhost:5000
```

If it works:

```text
Express ✅
```

---

# 10. Step 8 — Don't leave it running manually

This:

```bash
node server.js
```

isn't the ideal production process-management solution.

Instead:

```text
systemd
   ↓
Node.js
   ↓
Express
```

or:

```text
PM2
   ↓
Node.js
   ↓
Express
```

For the Linux knowledge you're learning, you should be comfortable explaining the systemd approach.

---

# 11. Step 9 — Build the React frontend

On your development machine, typically:

```bash
npm run build
```

This creates production-ready static files, commonly:

```text
dist/
```

for Vite-based React applications.

Conceptually:

```text
React source
     ↓
npm run build
     ↓
Production static files
     ↓
Nginx
```

Nginx can serve these files directly.

---

# 12. Step 10 — Configure Nginx

A common architecture is:

```text
Browser
   │
   ▼
 Nginx :80/:443
   │
   ├──────────────→ React static files
   │
   └── /api/* ───→ Express :5000
```

For example:

```nginx
server {
    listen 80;

    server_name example.com;

    root /var/www/myapp/dist;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:5000;
    }
}
```

The exact configuration depends on your application's routing and API paths.

---

# 13. Why Nginx?

Instead of exposing:

```text
Internet → Node :5000
```

you can use:

```text
Internet
    ↓
Nginx :80/443
    ↓
Node :5000
```

Nginx acts as a **reverse proxy**.

It can also:

* serve static files
* terminate HTTPS
* route requests
* handle connections efficiently
* provide a central entry point

---

# 14. Step 11 — HTTPS

Initially:

```text
Browser
   ↓
HTTP
   ↓
Nginx
```

Production should use:

```text
Browser
   ↓
HTTPS
   ↓
Nginx
   ↓
Express
```

A certificate authority such as Let's Encrypt can provide certificates, commonly managed with Certbot.

You'll study this in **Q92 — SSL certificates and HTTPS**.

---

# 15. Complete request flow

Suppose the user opens:

```text
https://example.com
```

The flow is:

```text
Browser
   ↓
DNS resolves example.com
   ↓
Public IP of VPS
   ↓
Nginx
   ↓
React static files
   ↓
Browser renders React
```

Then React calls:

```text
https://example.com/api/users
```

Flow:

```text
Browser
   ↓
Nginx
   ↓
/api/users
   ↓
Express :5000
   ↓
MongoDB
   ↓
Express response
   ↓
Nginx
   ↓
Browser
```

---

# 16. Where systemd fits

Your backend isn't just:

```text
Nginx → Node
```

There's a process manager behind Node:

```text
                     Ubuntu
                       │
                     systemd
                       │
                 myapp.service
                       │
                    Node.js
                       │
                    Express
```

So if Node crashes:

```text
Node crashes
     ↓
systemd detects failure
     ↓
restart policy
     ↓
Node starts again
```

# 18. Important interview point: MongoDB location

Don't say:

> "MongoDB must be installed on the same Ubuntu server."

That's not true.

You can have:

```text
VPS
├── Nginx
├── React
└── Node/Express

        │
        ▼

Managed MongoDB
```

or:

```text
VPS
├── Nginx
├── Node
└── MongoDB
```

Both architectures are possible.

For production, using a managed database can simplify backups, maintenance, scaling, and operational work.

---

# 🧠 Interview Answer

If asked:

> **"How would you deploy a MERN application on Ubuntu?"**

A strong junior-level answer:

> **"First, I provision an Ubuntu server and connect through SSH. I install the required software such as Git, Node.js and Nginx. I clone the application from GitHub, install backend dependencies, and configure production environment variables securely. I build the React frontend and configure Nginx to serve the frontend and reverse-proxy API requests to the Express server. I run the Node.js backend using a process manager such as systemd or PM2, configure HTTPS, and monitor the application and logs."**

That's a **very solid placement answer**.
