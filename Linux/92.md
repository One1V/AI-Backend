
# Q92 — What are SSL certificates and HTTPS?

This is an important deployment concept because you've already built:

```text
Browser
   ↓
Nginx
   ↓
Express
```

Now we make that communication **secure**.

---

# 1. HTTP vs HTTPS

### HTTP

```text
Browser
   ↓
HTTP
   ↓
Server
```

HTTP does **not provide encryption by itself**.

### HTTPS

```text
Browser
   ↓
HTTPS
   ↓
Server
```

HTTPS is essentially:

> **HTTP transmitted over TLS encryption.**

People often say "SSL certificate", but modern systems use **TLS**. SSL is the older technology.

---

# 2. Why do we need HTTPS?

Suppose you log into a website.

Your browser sends:

```text
email=ayush@example.com
password=123456
```

Without encryption, someone able to observe the network traffic could potentially read sensitive information.

With HTTPS:

```text
Browser
   ↓
🔐 Encrypted data
   ↓
Server
```

The traffic is protected from being read or modified by ordinary network attackers.

---

# 3. What does the certificate do?

A TLS certificate helps the browser verify:

> **"This server is authorized for this domain."**

Suppose you visit:

```text
https://example.com
```

The server presents a certificate for the domain.

The browser checks things including:

```text
Is the certificate valid?
        ↓
Is it expired?
        ↓
Is it for this domain?
        ↓
Is it trusted?
```

If the checks succeed:

```text
🔒 HTTPS connection established
```

---

# 4. Simple analogy

Think of HTTPS like sending a valuable package.

### HTTP

```text
You
 ↓
📦 Open package
 ↓
Internet
 ↓
Server
```

Someone intercepting it may be able to see what's inside.

### HTTPS

```text
You
 ↓
🔐 Locked package
 ↓
Internet
 ↓
Server
```

Only the intended endpoint can properly use the protected communication.

---

# 5. What happens when you visit HTTPS?

Suppose:

```text
https://example.com
```

The simplified flow is:

```text
Browser
   ↓
Connect to server
   ↓
TLS handshake
   ↓
Certificate verification
   ↓
Secure keys established
   ↓
Encrypted HTTP communication
```

Then:

```text
GET /api/users
```

travels through the encrypted connection.

---

# 6. Where does Nginx fit?

This is the important part for your deployment architecture.

Instead of:

```text
Browser
   ↓
HTTP
   ↓
Express
```

you commonly have:

```text
Browser
   ↓
HTTPS
   ↓
Nginx
   ↓
HTTP/internal connection
   ↓
Express :5000
```

Nginx handles the public TLS connection.

This is commonly called **TLS termination**.

---

# 7. What is TLS termination?

Suppose:

```text
Browser
      │
      │ HTTPS
      ▼
    Nginx
      │
      │ HTTP
      ▼
Express :5000
```

Nginx decrypts the incoming HTTPS connection and then forwards the request to Express.

So Nginx becomes the TLS termination point.

This is convenient because your Node application doesn't have to directly manage the public TLS connection.

---

# 8. Why can Nginx talk HTTP to Express?

Because Express is running locally on the same server:

```text
Nginx
 ↓
127.0.0.1:5000
 ↓
Express
```

The connection never needs to travel across the public Internet.

So a common architecture is:

```text
Internet
   │
   │ HTTPS
   ▼
Nginx :443
   │
   │ HTTP
   ▼
Express :5000
```

---

# 9. What is port 443?

Standard ports:

```text
80  → HTTP
443 → HTTPS
```

So:

```text
http://example.com
```

usually uses:

```text
:80
```

while:

```text
https://example.com
```

usually uses:

```text
:443
```

Your Express application might still use:

```text
:5000
```

internally.

---

# 10. How do you get a certificate?

A common option is **Let's Encrypt**, which provides free TLS certificates.

A tool such as Certbot can automate certificate issuance and configuration.

Conceptually:

```text
Domain
   ↓
Certificate Authority
   ↓
TLS certificate
   ↓
Nginx
   ↓
HTTPS
```

The exact commands depend on your Ubuntu/Nginx setup.

---

# 11. HTTP → HTTPS redirect

You generally want users to use HTTPS.

Nginx can redirect:

```text
http://example.com
       ↓
https://example.com
```

So:

```text
User
 ↓
HTTP :80
 ↓
Nginx
 ↓
301/308 redirect
 ↓
HTTPS :443
```

Then the secure connection is established.

---

# 12. What does the browser's 🔒 mean?

When you see:

```text
🔒 https://example.com
```

it generally means the browser has established a valid TLS connection and the certificate checks passed.

It does **not** mean:

> "The website itself is trustworthy."

This is an important distinction.

HTTPS protects the communication channel; it doesn't guarantee that the website is honest or that its application has no vulnerabilities.

---

# 13. HTTPS protects more than passwords

HTTPS protects data such as:

```text
Login credentials
Cookies
JWTs sent over HTTP headers
API responses
Personal information
Payment-related communication
```

For example:

```text
Authorization: Bearer <token>
```

should travel over HTTPS.

---

# 14. What happens without HTTPS?

Suppose your application uses:

```text
JWT
```

and sends:

```text
Authorization: Bearer ...
```

If you're transmitting sensitive authentication information over plain HTTP, the communication isn't adequately protected against network interception.

With HTTPS:

```text
Browser
   ↓
🔐 encrypted connection
   ↓
Nginx
   ↓
Express
```

This is why production authentication systems should use HTTPS.

---

# 15. Complete architecture

Now your deployment architecture becomes:

```text
                         INTERNET
                            │
                            ▼
                         Browser
                            │
                         HTTPS
                            │
                            ▼
                      Nginx :443
                            │
                     TLS termination
                            │
                            ▼
                    Express :5000
                            │
                            ▼
                         MongoDB
```

And Linux/systemd is underneath:

```text
                     Ubuntu Linux
                          │
                       systemd
                      /       \
                     ↓         ↓
                  Nginx      Node
                             Express
```

---

# 🧠 Interview Answer

If asked:

> **"What is HTTPS and how does SSL/TLS work?"**

A strong junior answer:

> **"HTTPS is HTTP secured using TLS. A TLS certificate helps the browser verify the server's identity and establish a secure encrypted connection. In a typical deployment, Nginx listens on port 443, handles the TLS connection, and forwards the request to the Express application running internally, for example on port 5000."**

If they ask:

> **"Why use Nginx for HTTPS?"**

Say:

> **"Nginx can terminate TLS at the public edge, handle certificates and HTTPS connections, and then reverse-proxy requests to the internal Node.js application."**
