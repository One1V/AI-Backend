
# Q94 — Mini Project: Deploy a Production-Ready Backend

This is the **final project of the Deployment module**. You're going to combine almost everything you've learned so far.

The goal is not to build a huge application. The goal is to understand **how a backend actually runs in production**.

---

# 🎯 What we're building

We'll deploy a simple Express backend on an Ubuntu VPS:

```text
                         INTERNET
                            │
                            ▼
                         HTTPS
                            │
                            ▼
                         Nginx
                       :443 / :80
                            │
                            ▼
                     Express / Node
                         :5000
                            │
                      systemd
                            │
                            ▼
                         MongoDB
```

With:

```text
GitHub → deployment
Linux → server
Nginx → reverse proxy
systemd → process management
MongoDB → database
.env → secrets
HTTPS → encryption
Logs → monitoring
Backup → recovery
```

# 1. Create your project

Your backend:

```text
production-backend/
├── server.js
├── package.json
├── package-lock.json
├── .env
├── .gitignore
└── README.md
```

Example:

```javascript
const express = require("express");

const app = express();

app.use(express.json());

app.get("/", (req, res) => {
    res.json({
        message: "Production backend is running"
    });
});

app.get("/api/health", (req, res) => {
    res.json({
        status: "OK"
    });
});

const PORT = process.env.PORT || 5000;

app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);
});
```

# 8. Create systemd service

Create:

```bash
sudo nano /etc/systemd/system/myapp.service
```

Example:

```ini
[Unit]
Description=Production Express Backend
After=network.target

[Service]
User=ayush
WorkingDirectory=/home/ayush/production-backend
ExecStart=/usr/bin/node server.js
Restart=on-failure
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

Then:

```bash
sudo systemctl daemon-reload
```

Start:

```bash
sudo systemctl enable --now myapp
```

Check:

```bash
sudo systemctl status myapp
```

# 10. Configure Nginx

Create/configure an Nginx server block.

For example:

```nginx
server {
    listen 80;

    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
    }
}
```

Then test:

```bash
sudo nginx -t
```

If successful:

```text
syntax is ok
test is successful
```

Reload:

```bash
sudo systemctl reload nginx
```

# 12. Add HTTPS

Now change:

```text

```

```text

```

```text

   ↓

   ↓
```

Use a trusted certificate authority such as Let's Encrypt and configure Nginx accordingly.

After HTTPS is working, you generally redirect HTTP traffic to HTTPS.

# 18. Backup

Your code is already in GitHub.

But your MongoDB data needs a separate backup strategy.

Conceptually:

```text
                 Production
                     │
             ┌───────┴───────┐
             ↓               ↓
          GitHub           MongoDB
             │               │
          code backup    database backup
```

If using MongoDB tools:

```bash
mongodump ...
```

and restore with:

```bash
mongorestore ...
```

For real production, you would normally consider managed database backups or independent backup storage.
