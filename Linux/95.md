
# Q95 — Explain the Complete Linux Filesystem

This is an **important Linux interview question** because Linux doesn't organize files the same way Windows does.

In Windows, you commonly see:

```text
C:\
D:\
E:\
```

Linux has **one main filesystem tree**:

```text
/
```

Everything starts from `/`.

---

# 1. The Linux filesystem

Think of `/` as the **root of a tree**:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin
├── srv
├── sys
├── tmp
├── usr
└── var
```

You don't need to memorize every directory for a backend interview.

Focus especially on:

```text
/
├── home
├── etc
├── var
├── usr
├── tmp
├── root
├── dev
├── proc
└── opt
```

---

# 2. `/` — Root directory

```text
/
```

is the **top-level directory**.

For example:

```text
/home/ayush/project
```

starts from:

```text
/
```

So:

```text
/
└── home
    └── ayush
        └── project
```

You can check it:

```bash
pwd
```

---

# 3. `/home` — User directories

Normal users usually have their personal directories here.

For example:

```text
/home/ayush
```

might contain:

```text
/home/ayush/
├── Documents
├── Downloads
├── Desktop
└── projects
```

When you previously worked with:

```text
~/Desktop/AI Backend/Linux
```

the `~` represents your home directory.

So approximately:

```text
~
↓
/home/ayush
```

---

# 4. `/etc` — Configuration

This is **very important for backend/deployment**.

`/etc` contains system and application configuration files.

For example:

```text
/etc/
├── nginx/
├── ssh/
├── systemd/
└── ...
```

Your Nginx configuration can be found under:

```text
/etc/nginx/
```

And systemd service definitions commonly live in:

```text
/etc/systemd/system/
```

For example, the service you created earlier:

```text
/etc/systemd/system/myapp.service
```

So remember:

> `/etc` → configuration.

---

# 5. `/var` — Variable data

`/var` contains data that changes frequently.

This is another **very important directory for backend engineers**.

For example:

```text
/var/log
```

contains logs.

You might find:

```text
/var/log/nginx/
```

with files such as:

```text
access.log
error.log
```

That's why when debugging Nginx you may use:

```bash
sudo tail -f /var/log/nginx/error.log
```

Another example:

```text
/var/lib
```

is commonly used for persistent application/system data.

So:

> `/var` → changing data, logs, caches, state, etc.

---

# 6. `/usr` — User-space programs and resources

`/usr` contains many installed programs, libraries and shared resources.

For example:

```text
/usr/bin
/usr/sbin
/usr/lib
/usr/share
```

You might find executable programs under:

```text
/usr/bin/
```

For example, depending on your installation:

```text
/usr/bin/node
```

could be the Node executable.

You can find a command's location with:

```bash
which node
```

or:

```bash
which nginx
```

---

# 7. `/bin` — Essential commands

Traditionally:

```text
/bin
```

contains essential command-line programs.

Examples include commands such as:

```text
ls
cp
mv
rm
cat
```

On modern Ubuntu systems, `/bin` may be a symbolic link into `/usr/bin` because of the **usr-merge** design.

For interviews, understand its purpose rather than worrying about the implementation detail.

---

# 8. `/sbin` — System administration commands

Traditionally:

```text
/sbin
```

contains system administration utilities.

For example, commands used for:

```text
Networking
Disk management
System administration
```

Modern distributions may also merge `/sbin` into `/usr/sbin`.

---

# 9. `/boot` — Boot files

Contains files required during the boot process.

For example:

```text
/boot
├── kernel
├── initramfs
└── bootloader-related files
```

You generally won't modify this during normal backend development.

---

# 10. `/dev` — Devices

Linux represents hardware and some virtual devices as files under:

```text
/dev
```

For example:

```text
/dev/null
```

is extremely useful.

You might see:

```bash
command > /dev/null
```

which discards the command's output.

You may also encounter:

```text
/dev/sda
```

for a disk device on some systems.

The important idea:

> Linux exposes devices through the filesystem interface.

---

# 11. `/proc` — Processes and kernel information

This one is particularly useful given the **processes module** you've studied.

```text
/proc
```

is a virtual filesystem containing information about processes and the kernel.

For example:

```text
/proc/1234
```

could correspond to process ID `1234`.

You can see:

```bash
ls /proc
```

and you'll find many numeric directories.

Those numbers are commonly PIDs.

So:

```text
/proc
   ├── 1
   ├── 250
   ├── 1345
   └── ...
```

connects directly to what you learned about:

```text
ps
top
processes
PIDs
```

---

# 12. `/sys` — Kernel/device information

```text
/sys
```

is another virtual filesystem.

It exposes information about:

```text
Hardware
Devices
Kernel subsystems
```

It's more important for system administration than everyday backend development.

---

# 13. `/tmp` — Temporary files

```text
/tmp
```

is used for temporary data.

For example:

```text
/tmp/something.tmp
```

Programs may create temporary files here.

Don't treat `/tmp` as permanent storage.

---

# 14. `/root` — Root user's home

This can confuse beginners.

```text
/root
```

is the home directory of the **root user**.

It is NOT the same thing as:

```text
/
```

Think:

```text
/
  ↓
Root of filesystem

/root
  ↓
Home directory of root user
```

---

# 15. `/opt` — Optional software

```text
/opt
```

is commonly used for optional or third-party software packages.

For example:

```text
/opt/myapplication
```

could contain an application installed outside the standard package layout.

You won't necessarily use it for every Node application.

---

# 16. `/mnt` and `/media`

### `/mnt`

Often used as a temporary mount point for filesystems:

```text
/mnt
```

### `/media`

Often used for automatically mounted removable media:

```text
/media
```

These aren't usually the most important directories for backend interviews.

---

# 17. `/srv` — Service data

```text
/srv
```

is intended for data served by system services.

For example, depending on the setup:

```text
/srv/www
```

could contain website data.

In practice, distributions and administrators may use other locations such as:

```text
/var/www
```

for web content.

---

# 18. The directories YOU should remember

For your backend/deployment work, prioritize these:

| Directory    | Remember it as                |
| ------------ | ----------------------------- |
| `/`        | Filesystem root               |
| `/home`    | Normal users' homes           |
| `/etc`     | Configuration                 |
| `/var/log` | Logs                          |
| `/var`     | Changing/application data     |
| `/usr/bin` | Programs                      |
| `/tmp`     | Temporary files               |
| `/root`    | Root user's home              |
| `/proc`    | Process/kernel information    |
| `/dev`     | Devices                       |
| `/opt`     | Optional/third-party software |

---

# 19. Connect it to your Nginx project

You've already worked with:

```text
/etc/nginx/
```

Why?

Because:

```text
/etc
 ↓
configuration
 ↓
nginx
 ↓
Nginx configuration
```

And your logs:

```text
/var/log/nginx/
```

because:

```text
/var
 ↓
changing data
 ↓
logs
```

And your systemd service:

```text
/etc/systemd/system/myapp.service
```

because:

```text
/etc
 ↓
configuration
 ↓
systemd
```

So the filesystem isn't just theory—you've already used it.

---

# 20. Your complete deployment filesystem

A simplified Ubuntu server might look like:

```text
/
├── etc/
│   ├── nginx/
│   │   └── nginx.conf
│   │
│   └── systemd/
│       └── system/
│           └── myapp.service
│
├── home/
│   └── ayush/
│       └── production-backend/
│           ├── server.js
│           ├── package.json
│           └── .env
│
├── var/
│   └── log/
│       └── nginx/
│           ├── access.log
│           └── error.log
│
├── usr/
│   └── bin/
│       └── ...
│
├── tmp/
│
└── proc/
```

This is a **very useful mental model** for backend deployment.

---

# 🧠 Interview Answer

If asked:

> **"Explain the Linux filesystem hierarchy."**

Don't try to list 30 directories.

Say:

> **"Linux has a single filesystem hierarchy starting at `/`. `/home` contains normal users' home directories, `/etc` contains system and service configuration, `/var` contains changing data such as logs, `/usr` contains user-space programs and resources, `/tmp` contains temporary files, `/root` is the root user's home directory, and `/proc` and `/sys` are virtual filesystems exposing process, kernel, and device information."**

Then give a backend example:

> **"For example, Nginx configuration is under `/etc/nginx`, Nginx logs are commonly under `/var/log/nginx`, and a systemd service can be defined under `/etc/systemd/system`."**

That answer is **more valuable in an interview** than memorizing the entire tree.

---

# 🔑 One-line memory trick

```text
/home → Users
/etc  → Configuration
/var  → Changing data + Logs
/usr  → Programs
/tmp  → Temporary
/proc → Processes
/dev  → Devices
/root → Root user's home
```
