# Why don't computers understand English?

Imagine I tell you:

> "Open the browser."

You immediately understand because your brain knows the meaning of "open" and "browser."

But a CPU is **not intelligent**.

A CPU is an electronic circuit made of **billions of transistors**.

A transistor has only two stable states:

* OFF → 0
* ON → 1

That's it.

It cannot understand words like:

```text
Open
File
Node
Express
```

It only understands patterns of **0s and 1s**.

---

Since electronic circuits can reliably distinguish between two voltage levels (high and low), binary is simple and robust.

English is ambiguous too ,suppose one has asked ----give me 2+4, wheraeas other asked please give me 2+4 , so there's difference and computers want precise thing not ambiguous.

# Real Backend Example

You write:

```javascript
app.listen(5000);
```

Internally:

```text
Express

↓

Node.js

↓

Operating System

↓

Machine Instructions

↓

CPU
```

The CPU never understands:

```javascript
app.listen()
```

It only executes machine-level instructions generated by software layers above it.

# Interview Answer

**Why do computers use binary instead of English?**

> Computers are built from electronic circuits that reliably represent two states (on and off). The CPU is designed to execute machine instructions encoded in binary, while higher-level programming languages exist to make it easier for humans to write software.

---

**Vim** is one of the most useful tools you'll learn as a backend engineer because you'll often edit files directly on remote Linux servers.

# What is Vim?

**Vim** is a **terminal-based text editor**.

Think of it as Linux's version of a lightweight code editor that runs inside the terminal.

It lets you edit files **without opening a graphical application like VS Code**.

---

# Why do we need Vim?

Imagine you've deployed your backend on a cloud server.

You connect using SSH:

```bash
ssh ubuntu@your-server-ip
```

Now you want to edit the Nginx configuration.

There's **no VS Code GUI** on the server.

Instead, you use:

```bash
vim /etc/nginx/nginx.conf
```

Vim opens the file directly in the terminal.

---

# Real Backend Example

Suppose your Express app is running on Ubuntu.

Your `.env` file has:

```text
PORT=5000
```

You want to change it to:

```text
PORT=8000
```

You run:

```bash
vim .env
```

Edit the file.

Save it.

Restart the server.

Done.

---

# Why not use VS Code?

You usually **don't have a desktop environment** on production servers.

Production servers are often accessed like this:

```text
Your Laptop

↓

SSH

↓

Ubuntu Server
```

Only the terminal is available.

That's why tools like Vim (or Nano) are important.

---

# Vim has Modes

This is what confuses beginners.

Unlike Notepad or VS Code, Vim has different modes.

### 1. Normal Mode

This is the default mode.

You **cannot type text** here.

You use it for navigation and commands.

---

### 2. Insert Mode

Press:

```text
i
```

Now you can type normally.

---

### 3. Command Mode

Press:

```text
Esc
```

Then type commands like:

```text
:w
```

Save.

```text
:q
```

Quit.

```text
:wq
```

Save and quit.

```text
:q!
```

Quit without saving.

# Vim vs Nano

| Nano                   | Vim                                      |
| ---------------------- | ---------------------------------------- |
| Easy to learn          | Steeper learning curve                   |
| Beginner-friendly      | Very powerful                            |
| Simple editing         | Fast navigation and editing              |
| Good for quick changes | Preferred by many experienced developers |

---

# Which one should you learn?

For now:

* Learn **Nano** first (easier).
* Learn **basic Vim** after that.

You don't need to become a Vim expert for backend interviews.

You should just know how to:

* Open a file
* Edit it
* Save
* Exit

# Mini Exercise

Create a file:

```bash
touch hello.txt
```

Open it:

```bash
vim hello.txt
```

Then:

1. Press `i`
2. Type:

```text
Hello Linux
```

3. Press `Esc`
4. Type:

```text
:wq
```

5. Press `Enter`

Now check:

```bash
cat hello.txt
```

Output:

```text
Hello Linux
```
