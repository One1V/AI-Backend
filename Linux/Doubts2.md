**Logs** are one of the most important concepts for backend engineers. When something breaks in production, the **first thing developers usually check is the logs**.

---

# What are Logs?

A **log** is simply a **record of events** that happen inside a program or system.

Think of it as a **diary** or **journal**.

Whenever something important happens, the application writes it down.

---

## Real-Life Analogy 📖

Imagine your school keeps an attendance register.

```text
09:00 - Ayush entered school
10:00 - Math class started
11:30 - Lunch break
03:00 - School ended
```

This is a **log** of the day's events.

Similarly, a server keeps records like:

```text
10:15:20 - Server started
10:15:35 - User Ayush logged in
10:16:02 - GET /api/users
10:16:05 - Database connected
10:16:10 - Error: Database timeout
```

---

# Why are logs important?

Suppose your website crashes at **2:00 AM**.

Users complain:

> "The website is not working."

How will you know what happened?

You check the logs.

Example:

```text
01:58:12 Database connected
01:59:45 MongoDB connection lost
02:00:01 Error: Database timeout
```

Now you know **why** the website stopped working.

---

# Example in Express

Imagine you have:

```javascript
app.get("/users", (req, res) => {
    console.log("GET /users requested");
    res.send("Users");
});
```

When someone visits:

```text
http://localhost:5000/users
```

The terminal shows:

```text
GET /users requested
```

That message is a **log**.

---

# Different Types of Logs

## 1. Application Logs

Generated by your application.

Example:

```text
Server started
User logged in
Payment successful
```

---

## 2. Error Logs

Generated when something goes wrong.

Example:

```text
MongoDB connection failed
JWT expired
File not found
```

---

## 3. Access Logs

Record every request.

Example:

```text
GET /users
POST /login
DELETE /notes/5
```

Nginx creates access logs automatically.

---

## 4. System Logs

Generated by Linux.

Example:

```text
SSH login successful
Nginx started
Docker restarted
```

These help diagnose operating system issues.

---

# Real Production Example

Suppose your architecture is:

```text
Browser
   ↓
Nginx
   ↓
Express
   ↓
MongoDB
```

User requests:

```text
GET /login
```

Logs might look like:

### Nginx Access Log

```text
GET /login 200
```

↓

### Express Log

```text
Login API called
```

↓

### MongoDB Log

```text
Query executed successfully
```

If something fails, these logs help you find **where** it failed.

---

# Where are logs stored?

Common Linux locations:

```text
/var/log/
```

Examples:

```text
/var/log/nginx/access.log
/var/log/nginx/error.log
```

Applications may also write logs to files such as:

```text
logs/app.log
```

or send them to logging services in production.

---

# How do we read logs?

Example:

```bash
cat app.log
```

Shows the whole file.

Large log?

```bash
tail -f app.log
```

This shows new log entries **live** as they are written.

Example output:

```text
Server started...
GET /users
POST /login
User authenticated
```

This is extremely useful when debugging.

# Interview Question

### What are logs?

A good answer:

> Logs are records of events generated by an application or system. They help developers monitor application behavior, debug issues, and understand what happened during execution.

---

# Best Practice

Instead of writing:

```javascript
console.log("Error");
```

Professional applications use logging libraries (like Winston or Pino in Node.js) that can include timestamps, log levels, and write logs to files or external systems.

Example:

```text
2026-08-05 10:30:15 ERROR Database connection failed
```

This is much more useful than a plain message.

## Backend Interview Tip

If your interviewer asks:

> **"Your server crashed. What is the first thing you check?"**

A strong answer is:

> **"I would check the application and server logs to identify errors, exceptions, or unusual events around the time of the crash."**

This reflects how backend engineers troubleshoot real production systems.

# In chrome at inspect what we see is this only in colsole log??

Yes, **partly**, but there is an important distinction.

When you open **Chrome DevTools (Inspect → Console)**, you are usually seeing **frontend (browser) logs**, not your backend server logs.

---

## 1. Browser Console Logs (Frontend)

Suppose your JavaScript contains:

```javascript
console.log("Button clicked");
```

When the user clicks a button, Chrome Console shows:

```text
Button clicked
```

This log exists **inside the browser**.

Flow:

```text
Your JavaScript
       ↓
Browser
       ↓
Chrome Console
```

---

## 2. Backend Logs

Suppose your Express server has:

```javascript
app.get("/", (req, res) => {
    console.log("Request received");
    res.send("Hello");
});
```

When someone visits your website:

```
http://localhost:5000
```

You **will not** see:

```text
Request received
```

in Chrome.

Instead, you'll see it in the terminal where your Express server is running.

Example:

```text
$ node server.js

Server running on port 5000
Request received
Request received
Request received
```

---

## Example Together

Suppose you have:

### Frontend

```javascript
console.log("Sending request...");

fetch("/api/users");
```

### Backend

```javascript
app.get("/api/users", (req, res) => {
    console.log("Users API called");
    res.json([]);
});
```

When you refresh the page:

### Chrome Console

```text
Sending request...
```

### Terminal

```text
Users API called
```

Two different places.

---

## In Production

When your app is deployed:

```text
Browser
      ↓
Internet
      ↓
Express Server
```

* **Frontend logs** → User's browser (Chrome DevTools Console).
* **Backend logs** → Linux server (terminal, log files like `/var/log`, or logging systems).

---

## What do the other tabs in Chrome DevTools show?

| Tab                   | Purpose                                                       |
| --------------------- | ------------------------------------------------------------- |
| **Console**     | JavaScript logs, errors, warnings                             |
| **Network**     | API requests (`fetch`, Axios), status codes, response times |
| **Elements**    | HTML and CSS                                                  |
| **Sources**     | JavaScript source code and debugging                          |
| **Application** | Cookies, Local Storage, Session Storage                       |
| **Performance** | Performance analysis                                          |

As a backend developer, you'll use **Console** and **Network** the most.

---

### Interview Tip

If asked:

> **Where does `console.log()` appear?**

The correct answer is:

* **Frontend `console.log()`** → Browser Console (Chrome DevTools).
* **Backend `console.log()`** → Terminal or server logs where the Node.js application is running.

This distinction is fundamental and is something every backend developer should understand.
