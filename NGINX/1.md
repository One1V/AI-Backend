# Question 1: What is Nginx?

**Nginx is software that sits between users and your application.** It receives requests from users, decides what to do with them, and either:

* serves files directly (HTML, CSS, JS, images), or
* forwards the request to a backend application like Express, Spring Boot, Django, etc.---

# 1. What is Nginx?

**Definition:**

Nginx (pronounced **"Engine-X"**) is a high-performance software that can work as:

* Web Server
* Reverse Proxy
* Load Balancer
* API Gateway
* HTTP Cache
* SSL/TLS Terminator

Although people call it a "web server," in modern applications its most important role is acting as a **reverse proxy** in front of backend servers.

---

# 2. Why was Nginx created?

Around the early 2000s, websites were becoming much larger.

Imagine YouTube launching.

Millions of users were trying to:

* Watch videos
* Upload videos
* Refresh pages
* Download thumbnails

Traditional web servers like Apache handled one connection with one process or thread.

As traffic increased:

```
1000 Users
↓

1000 Threads

↓

High RAM usage

↓

Slow server
```

This problem became famous as the **C10K Problem**.

> **C10K = How can one server handle 10,000 simultaneous connections?**

Igor Sysoev created Nginx in 2004 to solve this efficiently.

Problems begin.

* Accept requests
* Handle HTTPS
* Serve CSS
* Serve Images
* Serve Videos
* Execute API logic

Everything happens in one place.

This is inefficient.

Instead:

```

      │
      ▼

      │
      ▼
 Express Server
      │
      ▼
 MongoDB
```

Now each software does its own job.

# 5. What does Nginx actually do?

Suppose you visit

```
https://google.com
```

Your browser sends

```
GET /
```

Instead of directly reaching Google's backend,

it first reaches software like Nginx (or a similar reverse-proxy layer).

Nginx decides:

```
Is it an image?

Serve image.

↓

Is it CSS?

Serve CSS.

↓

API?

Send to backend.

↓

Malicious request?

Reject.

↓

HTTP?

Redirect to HTTPS.
```

The backend only receives requests that actually need application logic.

# 6. What happens internally?

Let's follow one request.

You type

```
https://mywebsite.com/profile
```

### Step 1

Browser asks DNS

```
Where is mywebsite.com?
```

Gets IP.

---

### Step 2

Browser connects to server.

---

### Step 3

Nginx receives request.

```
GET /profile
```

---

### Step 4

Nginx checks configuration.

Example:

```
If URL starts with /api

↓

Send to Express

Else

↓

Serve frontend
```

---

### Step 5

Express executes business logic.

Maybe

```
Find user

↓

MongoDB

↓

Return JSON
```

---

### Step 6

Express sends response.

```
JSON

↓

Nginx

↓

Browser
```

# 7. Where does Nginx sit?

A modern MERN architecture looks like this.

```
               Internet

                    │

             HTTPS Request

                    │

                 Nginx

      ┌──────────┴──────────┐

 Static Files           API Requests

      │                     │

React Build             Express

                              │

                           MongoDB
```

Notice:

React and Express never directly communicate with the Internet.

Nginx protects both.

# 9. WhatsApp example

Suppose 100 million people are online.

Every second:

```
Send message

↓

Receive message

↓

Load chats

↓

Load profile picture

↓

Update last seen
```

Companies at this scale use multiple networking layers (including reverse proxies like Nginx or similar technologies).

The reverse proxy layer:

```
Receives traffic

↓

Distributes requests

↓

Filters attacks

↓

Routes requests

↓

Backend processes only valid work
```

This separation improves scalability and security.

Express can serve:

```

CSS

Images

API
```

Nginx was.

```

↓

Express

↓

MongoDB
```

Each tool focuses on what it does best.

# 11. Why companies love Nginx

* Extremely fast
* Uses very little memory
* Handles many simultaneous connections
* Serves static files efficiently
* Acts as a reverse proxy
* Performs load balancing
* Supports HTTPS termination
* Can cache responses
* Stable and battle-tested
