
# Question 2: Why was Nginx created?

# Before Nginx

In the 1990s and early 2000s, most websites looked like this:

* Personal blogs
* Company websites
* News pages
* Small forums

Traffic was relatively low.

A server handling a few hundred users at once was considered good.

The most popular web server was **Apache**.

Apache worked well for those workloads.

---

# The Internet Changed

Around the early 2000s, websites became applications.

Instead of only reading pages, users started:

* Chatting
* Watching videos
* Uploading photos
* Shopping online
* Streaming music
* Using maps

Companies like Google, Amazon, and later Facebook needed servers that could handle **millions of users**.

---

# The Problem with Apache

Apache traditionally used a **process-per-request** or **thread-per-request** model.

Imagine 5 users visit your website.

```text
User 1 → Thread 1
User 2 → Thread 2
User 3 → Thread 3
User 4 → Thread 4
User 5 → Thread 5
```

Looks fine.

Now imagine:

```text
10,000 users

↓

10,000 threads
```

Every thread needs:

* Memory (RAM)
* CPU scheduling
* Stack space

As the number of users grows:

* RAM usage increases dramatically.
* CPU spends more time switching between threads (called **context switching**).
* Performance drops.

---

# The C10K Problem

This challenge became famous as the **C10K Problem**.

> **How can one server handle 10,000 simultaneous client connections efficiently?**

At that time, it was a major engineering challenge.

---

# Igor Sysoev's Solution

In 2004, software engineer **Igor Sysoev** developed Nginx.

Instead of creating one thread for every client, Nginx uses an **event-driven architecture**.

Apache:

```text
1000 Users

↓

1000 Workers
```

Nginx:

```text
1000 Users

↓

A few worker processes

↓

Each worker handles many users efficiently
```

This significantly reduced memory usage while increasing scalability.

We'll explore *how* this works in Question 9.

---

# Real-World Example: YouTube

Imagine YouTube receives requests for:

* Video thumbnails
* CSS files
* JavaScript
* User profiles
* Video streaming

Suppose **500,000 users** request the same thumbnail.

Without an efficient web server, the backend would waste resources serving identical static files.

With Nginx:

```text
User Request

↓

Nginx

↓

Static File?

↓

Return Immediately
```

The backend remains free to process uploads, recommendations, comments, and other dynamic work.

---

# Real-World Example: Amazon During a Sale

During a major sale, millions of users:

* Browse products
* Search items
* Add to cart
* Pay

If every request directly hit the backend:

* CPUs would be overloaded.
* Response times would increase.
* Customers could experience failures.

Instead:

```text
Customers

↓

Nginx

↓

Static assets served directly

↓

API requests forwarded to backend

↓

Backend handles business logic only
```

This separation improves scalability.

---

# Why Not Just Upgrade the Server?

Suppose your server has:

* 8 CPU cores
* 16 GB RAM

More users arrive.

Option 1:

Buy a bigger server.

Eventually, even that server has limits.

Option 2:

Use software that manages resources more efficiently.

That's exactly what Nginx provides.

---

# Engineering Philosophy

Nginx follows a simple principle:

> **Each component should do one job well.**

Nginx specializes in:

* Handling client connections
* Serving static content
* Managing HTTPS
* Routing requests
* Load balancing

Your application server specializes in:

* Authentication
* Business logic
* Database operations
* API responses

This separation makes systems easier to scale and maintain.

# Interview Questions

### Q1. Why was Nginx created?

**Answer:**

> Nginx was created in 2004 by Igor Sysoev to solve the C10K Problem—handling thousands of simultaneous client connections efficiently. It uses an event-driven architecture instead of creating one thread per connection, resulting in better performance and lower memory usage.

---

### Q2. What is the C10K Problem?

**Answer:**

> The C10K Problem is the challenge of designing a server capable of handling 10,000 concurrent client connections efficiently.

# Key Takeaways

* Nginx was built to solve the **C10K Problem**.
* Traditional thread-per-request models become inefficient at very high concurrency.
* Nginx's event-driven design allows it to handle many simultaneous connections with relatively few worker processes.
* Modern backend architectures use Nginx to let application servers focus on business logic while Nginx handles networking efficiently.
