
# Question 6: What is a Reverse Proxy

# First: What is a Proxy?

Imagine your college blocks Instagram.

You use a VPN or proxy.

Instead of going directly:

```text
You

↓

Instagram
```

you go through another server:

```text
You

↓

Proxy Server

↓

Instagram
```

Instagram thinks the request came from the proxy, not directly from you.

This is called a **Forward Proxy** because it works on behalf of the **client**.

---

# What is a Reverse Proxy?

Now reverse the situation.

Instead of hiding the **client**, we hide the **server**.

```text
Users

↓

Reverse Proxy (Nginx)

↓

Express
```

Users never communicate directly with Express.

They only know Nginx.

---

# Real Example

Suppose your backend runs on:

```text
http://localhost:5000
```

If there is no Nginx:

```text
Browser

↓

Express:5000
```

Everyone knows your backend port.

Now with Nginx:

```text
Browser

↓

https://myapp.com

↓

Nginx

↓

Express:5000
```

The browser doesn't know (or need to know) that Express is running on port 5000.

---

# Why is it called "Reverse"?

Because it's the **opposite** of a forward proxy.

### Forward Proxy

Protects the **client**.

```text
Client

↓

Proxy

↓

Internet
```

---

### Reverse Proxy

Protects the **server**.

```text
Internet

↓

Reverse Proxy

↓

Server
```

---

# Internal Request Flow

Suppose you visit:

```text
https://myapp.com/api/login
```

### Step 1

Browser sends:

```http
POST /api/login
```

---

### Step 2

Nginx receives it.

---

### Step 3

Nginx checks its configuration.

It sees:

```nginx
location /api {
    proxy_pass http://localhost:5000;
}
```

Meaning:

> "Any request starting with `/api` should be sent to the Express server on port 5000."

---

### Step 4

Nginx forwards the request.

```text
Nginx

↓

Express
```

---

### Step 5

Express processes:

* Validate user
* Check password
* Query MongoDB
* Generate JWT

---

### Step 6

Express returns:

```json
{
"token":"..."
}
```

---

### Step 7

Nginx sends that response back to the browser.

The browser thinks the response came from **myapp.com**.

It doesn't know Express exists.

---

# Why do companies use Reverse Proxies?

## Reason 1: Hide Backend Servers

Suppose you have:

```text
Express

↓

Port 5000
```

Without Nginx:

Everyone can directly attack port 5000 (if it's publicly exposed).

With Nginx:

```text
Internet

↓

Nginx

↓

Express
```

Only Nginx is exposed publicly.

---

## Reason 2: HTTPS

Instead of configuring SSL certificates in every backend:

```text
Users

↓

HTTPS

↓

Nginx

↓

HTTP

↓

Express
```

Nginx decrypts HTTPS and forwards the request inside your trusted network.

---

## Reason 3: Multiple Backend Servers

Imagine one Express server isn't enough.

```text
Express 1

Express 2

Express 3
```

Nginx decides where each request goes.

```text
Users

↓

Nginx

↓

Express 1

Express 2

Express 3
```

This is load balancing.

---

## Reason 4: Different Services

Suppose you have:

```text
React

Express API

Python AI Service

Spring Boot Payment Service
```

Nginx routes requests:

```text
/api

↓

Express

----------------

/ai

↓

Python

----------------

/payment

↓

Spring Boot
```

Users still access everything through:

```text
https://myapp.com
```

They don't need to know about different ports or servers.

---

# Real-World Example: Netflix

A user opens Netflix.

Requests include:

* Homepage
* Movie posters
* Recommendations
* Search
* Playback

A reverse-proxy layer (such as Nginx or similar technology) receives requests and routes them to the correct backend service.

```text
User

↓

Reverse Proxy

├── Posters Service
├── Search Service
├── Recommendation Service
└── Playback Service
```

The user interacts with a single domain, while the proxy handles routing internally.

---

# MERN Example

Suppose your app has:

```text
React → Port 3000

Express → Port 5000
```

Nginx configuration might route:

```text
/

↓

React

----------------

/api

↓

Express
```

To users, everything appears under one website:

```text
https://myapp.com
```

# Interview Questions

### Q1. What is a reverse proxy?

**Answer:**

> A reverse proxy is a server that sits between clients and backend servers. It receives client requests, forwards them to the appropriate backend, and returns the backend's response. It hides backend servers, enables HTTPS termination, load balancing, and request routing.

---

### Q2. Why use Nginx as a reverse proxy?

**Answer:**

> Because it improves security by hiding backend servers, manages HTTPS, serves static files efficiently, supports load balancing and caching, and routes requests to the correct application servers.

# Key Takeaways

* A **reverse proxy stands in front of servers**, not clients.
* Clients communicate with Nginx, not directly with Express.
* Nginx forwards requests to the appropriate backend.
* Reverse proxies improve **security, scalability, routing, and HTTPS management**.
* This pattern is standard in modern backend architectures, including MERN, Java, Python, Go, and microservices.
